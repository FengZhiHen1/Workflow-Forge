# 编程领域格式契约 (Format Contract)

> 本文件定义编程领域特有的格式规则。
>
> **通用 Obsidian 格式规则**（frontmatter 结构、双链、标题层级、列表、表格嵌套、高亮避让、文本格式化）见 `references/obsidian-format-rules.md`。

## 文件 Frontmatter 规范（编程领域）

通用 frontmatter 结构见 `obsidian-format-rules.md`。编程领域在通用字段基础上扩展以下字段：

```yaml
---
aliases:
course: {课程名}      # 课程/教材名（如 "C++ Primer"、"Rust 程序设计"）
type: {类型}          # 取值见下方类型表
status: 待整理
mastery: {1-5}
date_created: YYYY-MM-DD
language: {语言名}    # 显式声明编程语言（如 Python、C++、Rust、Go）
standard: {标准版本}  # 语法/语义/API/工具链 必须标注标准版本；原则/对比可选
library: {库名}       # 仅在 type: API 中使用。stdlib 表示标准库，第三方库写具体名称
platform: {平台}      # 仅在工具链或平台特定笔记中使用，普通笔记省略
source: {教材/文档}   # 知识来源（教材名、官方文档链接等）
tags:
  - 编程笔记
---
```

### 字段约束说明

- **`language` 显式声明**：不通过文件夹路径隐含，因为编程笔记的跨语言引用极其常见（如 C++ RAII 对比 Python `with`）。
- **`standard` 分层要求**：语法/语义/API/工具链 必须标注标准版本；原则可选。主文件聚焦**最新标准**，历史差异在正文 `## 版本演进` 中展开。
- **`library: stdlib`**：标准库显式写 `stdlib`，与第三方库（`requests`、`Flask`）统一字段，避免查询时的歧义。
- **`library` 字段约束**：仅在 `type: API` 中使用。其他类型若涉及第三方库示例，在正文标注，不写入 frontmatter，防止元数据污染。
- **`platform` 可选**：仅在工具链或平台特定笔记中使用，普通笔记省略以保持精简。
- **`status` 不引入"已废弃"**：特性废弃是语义属性，不是笔记状态。废弃特性笔记保持 `已整理`，在正文中用 `> [!warning]` 标注废弃信息，保留历史参考价值。
- **`tags` 自由 + 白名单**：领域标签（如 `内存管理`、`并发`、`泛型`）建议优先使用白名单，但不强制，避免领域扩展时卡住。

编程领域的 `type` 取值如下：

| type 值 | 说明 |
|---------|------|
| 书MOC / 节MOC | MOC 文件 |
| 语法 | 语法类原子笔记 |
| 语义 | 语义类原子笔记 |
| API | API 类原子笔记 |
| 惯用法 | 惯用法类原子笔记 |
| 工具链 | 工具链类原子笔记 |
| 原则 | 原则类原子笔记 |
| 对比 | 对比类原子笔记 |

## Callout 映射表

所有编程内容必须使用 Obsidian 原生 Callout，映射关系如下：

| 编程要素 | Callout 语法 | 折叠 |
|----------|-------------|------|
| 语法 | `> [!abstract] 语法：[名称]` | 否 |
| 语义 | `> [!info] 语义：[名称]` | 否 |
| API | `> [!tip] API：[名称]` | 否 |
| 惯用法 | `> [!info] 惯用法：[名称]` | 否 |
| 工具链 | `> [!todo] 工具链：[名称]` | 否 |
| 原则 | `> [!abstract] 原则：[名称]` | 否 |
| 对比 | `> [!warning] 对比：[名称]` | 否 |
| 补充 / 注意 | `> [!tip] 补充/注意` | 否 |
| 完整可运行示例 | `> [!example]- 示例` | **是** |
| 错误/UB/陷阱复现代码 | `> [!warning] 陷阱/反模式` | **否** |
| 逻辑脉络（MOC 专用） | `> [!abstract]- 逻辑脉络图景` | **是** |

**铁律**：
- 完整可运行示例**必须折叠**（`-` 后缀），其他 Callout 默认展开
- 陷阱/反模式代码**禁止折叠**（陷阱价值在于"一眼看到错误"）
- Callout 标题必须包含类别标识（如 `语法：`、`语义：`、`API：`）
- 一个 Callout 只对应一个编程要素，禁止合并

## 代码规范：环境绑定与分层展示

代码在编程笔记中的角色远比数学公式复杂——它既是**知识载体**，又是**可执行对象**。因此我们设计了分层容器策略：

| 场景 | 容器 | 折叠策略 | 验证要求 |
|------|------|----------|----------|
| 短片段/核心语法 | fenced code block | 不折叠 | 可选 |
| 完整可运行示例 | `> [!example]-` | **折叠** | 建议标注 |
| 错误/UB/陷阱复现代码 | `> [!warning]` | **不折叠** | **必须标注** |

**环境标注**（`# env: Python 3.11.4 / CPython / macOS 14`）不是过度工程，而是**时间戳**——编程知识高度依赖版本，没有环境信息的代码片段在两年后可能变成误导。

**注释语言**：中文为主，正文承担详细解释。这是**个人学习笔记**，不是开源项目，优先保证理解速度而非工程规范。
