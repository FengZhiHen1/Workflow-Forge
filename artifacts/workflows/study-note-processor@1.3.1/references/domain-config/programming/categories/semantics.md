# 语义类原子笔记写作规范 (Semantics Note Specification)

## 适用分类

YAML `type: 语义`，Callout `> [!info] 语义：[名称]`。

> 语义笔记回答"运行期实际发生什么？"记录代码在特定环境下的行为保证，而非"怎么写"。

## 内容布局（必须按此顺序）

```markdown

aliases:

status: 待整理

standard: {标准版本}
tags:
  - 编程笔记
---
# {学术描述性名称}

> [!info] 语义：{名称}
> 运行期行为的完整陈述。所有条件、边界、保证必须完备。
> ```{language}
> # env: {语言} {版本} / {实现} / {平台}
> # 核心行为示例（简短片段）
> ```

> [!tip] 核心思路
> （可选）用一句话说明该语义在程序执行模型中的角色。

## 行为保证与边界

1. **正常行为**：在标准条件下发生什么？
2. **边界行为**：在边界条件下发生什么？（空值、零长度、溢出等）
3. **未定义行为**（如适用）：哪些情况属于 UB？编译器可做什么？

> [!example]- 完整行为示例
> ```{language}

> ```

> - 行为与直觉不符的边界情况
> - 特定编译器/解释器的实现差异

## 各节写作要求

### `> [!info] 语义：[名称]`
- **位置**：紧接 H1 标题之后
- **内容**：运行期行为的完整陈述，**所有**边界条件必须列全
- **格式**：按"若...则..."或"当...时..."的结构描述行为
- **代码**：包含 1 个简短的核心行为示例

### `> [!tip] 核心思路`（可选）
- **用途**：为复杂的语义提供一个"一句话总结"
- **示例**："Python 的赋值操作不是复制数据，而是让新变量引用同一个对象"

### `## 行为保证与边界`
- **正常行为**：标准条件下的执行结果
- **边界行为**：边界条件下的执行结果（空值、零、最大/最小值等）
- **未定义行为**（UB）：如适用，明确列出哪些输入会导致 UB，以及 UB 的潜在后果

### `> [!example]- 完整行为示例`
- **折叠**：必须使用 `-` 后缀折叠
- **内容**：可运行的完整代码，展示该语义在各种条件下的行为
- **环境标注**：必须包含 `# env: ...` 注释

### `## 理解与细节`
- **位置分析**：该语义在语言整体执行模型中的位置
- **常见误用**：哪些写法会导致对该语义的误解？
- **实现差异**：不同编译器/解释器/版本之间是否有行为差异？

### `> [!warning] 陷阱`
- **铁律**：代码**禁止折叠**
- **重点**：行为与直觉不符的地方——这是语义笔记的核心价值

### `## 关联脉络`
- **上游**：该语义依赖的语法规则和语言机制
- **下游**：依赖此语义的 API 设计、惯用法、性能优化策略

## 语义 vs 语法的区分

| 维度 | 语法类 | 语义类 |
|------|--------|--------|
| 标题 | "语法：XXX" | "语义：XXX" |
| 核心内容 | 合法/非法写法 | 运行期行为保证 |
| 是否有代码示例 | 有（展示语法形式） | 有（展示行为结果） |
| 典型问题 | "这样写合法吗？" | "这样写运行时会怎样？" |
| 折叠节 | 无 | 完整示例（`[!example]-`） |
