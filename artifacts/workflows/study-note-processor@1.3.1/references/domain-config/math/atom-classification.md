# 数学原子知识点分类体系 (Atom Classification System)

## 概览

本文件定义数学学科中原子知识点的分类体系。每个知识点按其数学语义被归入以下类别之一，该分类决定其在 Obsidian 中的 Callout 类型、YAML frontmatter 的 `type` 字段值，以及写作规范。

## 分类总表

| 类别 | 英文 | YAML type | Callout | 语义说明 | Mermaid 节点形状 |
|------|------|-----------|---------|---------|-----------------|
| 定义 | Definition | `定义` | `[!abstract]` | 精确描述数学对象或概念的含义 | `[[]]`（矩形） |
| 定理 | Theorem | `定理` | `[!info]` | 经严格证明成立的数学命题 | `{}`（菱形） |
| 公理 | Axiom | `定理` | `[!info]` | 不加证明即接受的假设，作为推理基础 | `{}`（菱形） |
| 性质 | Property | `性质` | `[!todo]` | 由定义或定理推导出的重要属性 | `[[]]`（矩形） |
| 引理 | Lemma | `引理` | `[!todo]` | 为证明定理服务的辅助性中间命题 | `[[]]`（矩形） |
| 推论 | Corollary | `推论` | `[!todo]` | 由定理直接导出的简单结论 | `[[]]`（矩形） |

## 各类别详细说明

### 定义 (Definition) — `[!abstract]`

**语义**：首次引入新概念时，给出严格而精确的描述。定义是知识体系的原子原点，所有后续命题的证明都必须回溯到定义。

**典型示例**：
- 常数项无穷级数的定义
- 函数极限的 `\varepsilon`-`\delta` 定义
- Riemann 积分的定义

**判定标准**：
- 是否在"构造"一个新概念？
- 是否回答"XX 是什么？"这一本质问题？
- 是否有后续内容依赖此概念？

**注意事项**：
- 定义无"对错"之分，但需注意等价定义的多种形式
- 一个概念可能存在多种等价定义，各定义应独立成篇并通过双链关联

### 定理 (Theorem) — `[!info]`

**语义**：经严格证明成立的数学命题，具有独立的理论价值或应用价值。定理是数学知识体系的核心骨架。

**典型示例**：
- Cauchy 收敛准则
- 微积分基本定理
- 隐函数定理

**判定标准**：
- 是否是一个"如果...则..."形式的命题？
- 是否附有严格证明？
- 是否具有独立的引用价值（在后续多个上下文被引用）？

**与性质的区分**：定理是体系中的"主角"，性质是主角的"特征描述"。如果某个命题在逻辑链中处于核心位置并且被广泛引用，它应当是定理；如果它描述的是某对象的内在属性，它应当是性质。

### 公理 (Axiom) — `[!info]`

**语义**：不证自明或约定接受的命题，构成逻辑推演的起点。在数学分析中，实数完备性相关内容常被作为公理。

**典型示例**：
- 确界原理
- 区间套定理（可作为公理，也是定理）
- Zorn 引理（在集合论中等价于选择公理）

**判定标准**：
- 是否被教材明确定义为"公理"或作为出发点的假设？
- YAML type 统一为 `定理`，Callout 使用 `[!info]`（与定理共用视觉风格）

### 性质 (Property) — `[!todo]`

**语义**：数学对象的内在属性、特征或由定义直接导出的结论。性质通常不涉及复杂的证明链条，更多在于"刻画"对象行为。

**典型示例**：
- 收敛级数的线性性质
- 级数的有限项不变性
- 收敛级数的加括号性质
- 连续函数的局部有界性

**判定标准**：
- 是否描述某对象"具有"的某种特征？
- 其证明是否相对简短（≤ 定理的证明复杂度）？
- 是否处在定理的"下游"——用于丰富对对象的理解？

**与引理的区别**：性质描述的是内在属性（"XX 具有 XX 特征"）；引理则是为证明某个更大定理而服务的工具命题。

### 引理 (Lemma) — `[!todo]`

**语义**：为证明重要定理而预先设立的辅助命题。引理自身可能不具备独立引用价值，但在定理的证明中起到关键的桥梁作用。

**典型示例**：
- 在证明某个收敛性定理前，先证明一个不等式引理
- Rolle 定理（作为 Lagrange 中值定理的引理）

**判定标准**：
- 是否主要是为证明某个更大的定理服务？
- 是否较少在上下游被独立引用？

### 推论 (Corollary) — `[!todo]`

**语义**：由定理直接导出的简单命题，通常只需一两步推理即可完成。推论本身不包含复杂的证明。

**典型示例**：
- 由单调有界原理直接得出单调递减有下界数列收敛
- 由 Cauchy 准则取 p=1 得通项趋于零

**判定标准**：
- 是否可由某定理"立即得到"？
- 其推理步骤是否 ≤ 3 步？

### 方法 (Method) — `[!info]`

**语义**：用于解决问题或执行判别的操作步骤、算法或策略。方法强调"怎么用"而非"是什么"。

**典型示例**：
- 任意项级数的判别步骤
- 交换积分次序的方法
- 分部积分法

**判定标准**：
- 核心内容是否为"步骤"或"流程"？
- 是否更多强调"实践操作"而非"理论证明"？
- 是否通常附有例题说明？

### 反例 (Counterexample) — `[!warning]`

**语义**：用来证伪某个命题的具体实例。反例在数学中至关重要的，它帮助我们精确理解定理的适用范围。

**典型示例**：
- 调和级数发散（通项趋于零但级数发散的反例）
- Dirichlet 函数（有界但不 Riemann 可积的反例）

**判定标准**：
- 核心价值是否是"证伪"某个命题？
- 是否用于说明某条件的必要性（去掉该条件则结论不成立）？

**注意事项**：
- 反例通常是某个定理"必要条件"的佐证，应与定理聚类而不是独立存在
- 在 MOC 中，反例通常作为其关联定理的子项缩进

## 主从关系判定准则

在 MOC 的原子点列表中，使用 4 空格缩进表达逻辑从属关系。判定 B 是否为 A 的子项：

1. **推论关系**：B 是 A 的直接推论（A 是定理，B 是其推论 → B 缩进于 A 下）
2. **工具关系**：B 的存在完全为 A 服务（A 是定理，B 是其引理 → B 缩进于 A 下）
3. **反例关系**：B 是 A 的反例（A 是定理/性质，B 是其反例 → B 缩进于 A 下）
4. **细分关系**：B 是 A 的特殊形式或极限形式（A 是方法/定理，B 是其特例 → B 缩进于 A 下）

**独立判定**：若 B 在后续多处被引用，即使它是为 A 服务的引理，也应作为一级列表独立存在，并在逻辑脉络图景中说明其"基石"地位。

## 原子点命名后缀规范

### 命名格式
```
{学术描述性名称}{身份后缀}
```

### 后缀表

| 类别 | 后缀 | 示例 |
|------|------|------|
| 定义 | `定义` | `常数项无穷级数定义` |
| 定理 | `定理` | `级数收敛的Cauchy准则定理` |
| 公理 | `定理`（与定理共用后缀） | `确界原理定理` |
| 性质 | `性质` | `收敛级数的线性性质` |
| 引理 | `定理` | `Leibniz判别法定理` |
| 推论 | `推论` | `单调有界推论收敛` |
| 方法 | `方法论` / `方法` | `任意项级数判别步骤方法论` |
| 反例 | `的反例` | `调和级数发散的反例` |

### 命名铁律
1. **严禁编号**：禁止 `性质 1.1`、`Definition 1` 等形式
2. **学术描述性**：名称应准确反映数学内涵，而非序号
3. **唯一性**：同一 Vault 内双链名必须唯一（通过学术名称自然保证）
4. **后缀一致性**：名称后缀必须与 YAML `type` 和 Callout 类型一致
