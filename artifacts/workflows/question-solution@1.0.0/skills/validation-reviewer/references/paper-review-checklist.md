# Reference：论文评审视角检查清单

本文件从数学建模竞赛论文评审的角度，提供对论文呈现质量的攻击维度。在 P4-对抗阶段（若 P5 已有论文草稿）或作为 P2-对抗的补充审查使用。

> 原则：**模型再好，论文写不清楚也是零分**。评委看不到代码，只能看到论文。

---

## 论文呈现攻击维度

### PR-01 结果呈现攻击

**评委视角**："你算出了结果，但我一眼看不懂这意味着什么。"

**检查要点**：
- [ ] 关键结果是否以**表格/图表**呈现，而非纯文字描述？
- [ ] 图表是否**自解释**（标题、坐标轴标签、单位、图例是否完整）？
- [ ] 数字是否经过**合理修约**（不要保留 8 位小数）？
- [ ] 结果是否有**直观的解释**（如"600人"能否对应到具体场景）？
- [ ] 关键结论是否有**加粗/高亮**，便于评委快速定位？

**致命性判定**：
- 🔴 致命：关键结果完全没有图表呈现、或图表缺失坐标轴标签导致无法解读
- 🟡 高危：图表可读性差、数字修约不当、缺少关键结果的直观解释
- 🟢 提示：可视化风格可优化、可补充更多对比图表

---

### PR-02 敏感性分析呈现攻击

**评委视角**："你的模型对参数敏感吗？敏感的话你的结论还可靠吗？"

**检查要点**：
- [ ] 是否进行了**敏感性分析**？（不是有没有做，而是**有没有在论文中呈现**）
- [ ] 敏感性分析是否覆盖了**关键参数**？（而非只分析了一个无关紧要的参数）
- [ ] 结果是否以**可视化**呈现（如 tornado 图、蜘蛛图）？
- [ ] 敏感性分析的**结论**是否明确？（如"参数 X 在 ±20% 范围内变化时，结果变化 < 5%，模型鲁棒"）
- [ ] 是否区分了**一阶效应**和**交互效应**？

**致命性判定**：
- 🔴 致命：完全没有敏感性分析、或只分析了无关参数
- 🟡 高危：敏感性分析不完整（缺少关键参数）、或只有表格没有可视化
- 🟢 提示：可视化可更丰富、可补充交互效应分析

---

### PR-03 假设呈现攻击

**评委视角**："你做了哪些假设？这些假设合理吗？如果假设不成立呢？"

**检查要点**：
- [ ] 论文中是否**明确列出了所有关键假设**？（不能藏在正文里）
- [ ] 每个假设是否有**合理性论证**？（引用数据/文献/常识）
- [ ] 假设是否按**强度分级**（强/中/弱）？
- [ ] 对**强假设**是否有**敏感性分析**或**放松假设的讨论**？
- [ ] 是否讨论了**假设不成立时的影响**？（如"若假设 X 不成立，模型将..."）

**致命性判定**：
- 🔴 致命：关键假设完全未声明、或强假设没有任何合理性论证
- 🟡 高危：假设列表不完整、缺少假设不成立的讨论、强假设未做敏感性分析
- 🟢 提示：假设的表述可更严谨、可补充更多文献支撑

---

### PR-04 创新性呈现攻击

**评委视角**："你的创新点是什么？和别人的方法有什么区别？"

**检查要点**：
- [ ] 论文是否**明确声明了创新点**？（不能指望评委自己发现）
- [ ] 创新点是否**与现有方法进行了对比**？
- [ ] 创新点的**价值**是否被充分论证？（不是"我用了新方法"，而是"新方法比旧方法好在 X"）
- [ ] 创新是否只是**换皮**？（如把 LSTM 换成 GRU 就声称创新）
- [ ] 是否引用了**相关文献**来证明创新点的独特性？

**致命性判定**：
- 🔴 致命：完全没有声明创新点、或创新点只是换皮（评委一眼看穿）
- 🟡 高危：创新点声明模糊、缺少与现有方法的对比、价值论证不足
- 🟢 提示：创新性表述可更突出、可补充更多对比实验

---

### PR-05 局限性呈现攻击

**评委视角**："你的模型有哪些不足？你有没有诚实地承认？"

> **关键洞察**：好的论文会**主动、诚实地讨论局限性**，而不是等评委来挑刺。主动承认局限性反而增加可信度。

**检查要点**：
- [ ] 论文是否**专门有一节讨论局限性**？
- [ ] 局限性是否**具体**？（不是"模型有不足"，而是"由于假设 X，模型无法处理 Y 场景"）
- [ ] 局限性是否与**前文分析一致**？（不能前面说模型完美，后面又说局限性很大）
- [ ] 是否提出了**改进方向**？（"未来可以考虑..."）
- [ ] 局限性的**数量是否适当**？（太少显得不诚实，太多显得模型太差）

**致命性判定**：
- 🔴 致命：完全没有讨论局限性、或局限性与前文自相矛盾
- 🟡 高危：局限性过于笼统、或遗漏了明显的关键局限
- 🟢 提示：局限性可更深入、改进方向可更具体

---

### PR-06 符号与术语一致性攻击

**评委视角**："你前面定义的符号和后面用的怎么不一样？"

**检查要点**：
- [ ] 所有数学符号是否在**首次出现时定义**？
- [ ] 同一符号在**全文是否一致**？（不能前面 $x$ 是决策变量，后面 $x$ 变成参数）
- [ ] 符号表是否**完整**？（建议在论文附录或正文中提供符号表）
- [ ] 术语是否**统一**？（不能混用"顾客/客户/用户"指同一对象）
- [ ] 跨文档（P1b/P2/P3/P4）的符号定义是否**一致**？

**致命性判定**：
- 🔴 致命：核心符号定义前后矛盾、或同一符号在不同章节含义不同且无说明
- 🟡 高危：符号定义不完整、缺少符号表、术语混用
- 🟢 提示：符号表可更规范、术语可更统一

---

### PR-07 模型描述清晰度攻击

**评委视角**："你的模型是怎么工作的？我看完论文还是不懂。"

**检查要点**：
- [ ] 模型是否以**流程图/伪代码/结构图**呈现？
- [ ] 模型的**输入→处理→输出**流程是否清晰？
- [ ] 关键公式是否有**文字解释**？（不能只给公式不给解释）
- [ ] 复杂算法是否有**步骤分解**？（不能一步跳到最终结果）
- [ ] 是否提供了**运行示例**？（一个小规模案例展示模型如何工作）

**致命性判定**：
- 🔴 致命：模型描述完全缺失、或只有公式没有解释导致评委无法理解
- 🟡 高危：模型描述不完整、缺少流程图、关键步骤跳跃
- 🟢 提示：描述可更详细、可补充更多示例

---

## 论文评审攻击流程

在 P4-对抗阶段，若 P5 已有论文草稿或建模报告：

1. 读取论文草稿/建模报告
2. 按 PR-01 至 PR-07 逐条检查
3. 对每条检查项给出：
   - 当前状态（通过/部分通过/未通过）
   - 具体证据（引用论文中的段落/图表/公式）
   - 评委可能的质疑
   - 修改建议
4. 汇总论文呈现质量评分

## 论文呈现质量评分

| 维度 | 权重 | 得分(0-10) |
|:---|:---:|:---:|
| 结果呈现 (PR-01) | 20% | |
| 敏感性分析呈现 (PR-02) | 15% | |
| 假设呈现 (PR-03) | 15% | |
| 创新性呈现 (PR-04) | 15% | |
| 局限性呈现 (PR-05) | 10% | |
| 符号一致性 (PR-06) | 10% | |
| 模型描述清晰度 (PR-07) | 15% | |
| **综合评分** | **100%** | |

- 综合评分 < 5：论文呈现存在致命缺陷，必须重写
- 综合评分 5-7：存在高危问题，必须修改
- 综合评分 > 7：基本合格，可进入微调
