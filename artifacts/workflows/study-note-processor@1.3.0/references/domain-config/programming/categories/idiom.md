# 惯用法类原子笔记写作规范 (Idiom Note Specification)

## 适用分类

YAML `type: 惯用法`，Callout `> [!info] 惯用法：[名称]`。

> 惯用法笔记与语法/API 笔记的不同在于：它强调**代码模式**和**适用场景**，而非语言规则或接口契约。

## 各节写作要求

### `> [!info] 惯用法：[名称]`
- **内容**：一句话归纳——场景 + 代码模式 + 解决的痛点
- **示例**："Python 中管理资源释放的标准惯用法。通过 `with` 语句确保 `__enter__` 和 `__exit__` 成对调用，避免资源泄漏。"
- **注意**：不要在此处展开完整代码，代码放在独立的 `## 代码模式` 节

### `## 适用场景`
- **内容**：该惯用法最适用的上下文条件
- **格式**：无序列表 `- `
- **重要性**：这是惯用法的"安全边界"——在不合适的场景使用可能导致反效果

### `## 代码模式`
- **格式**：fenced code block，展示惯用法的"标准写法"（像模板一样）
- **要求**：
  - 用 `{占位符}` 标注可替换部分
  - 用 `// ...` 标注可扩展部分
  - 代码应可直接复制并填入具体内容后运行

### `> [!tip] 补充/注意`
- **与相似惯用法对比**：如"RAII vs try-finally vs with"的区别
- **常见错误**：如"在 `with` 块外访问已关闭的文件对象"
- **技巧提示**：如"自定义上下文管理器时，`__exit__` 的异常参数可用于抑制异常"

### `> [!example]- 完整示例`
- **折叠**：使用 `-` 后缀折叠
- **内容**：展示惯用法在真实场景中的完整应用，而非模板
- **环境标注**：必须包含 `# env: ...`

### `> [!warning] 不要这样做`
- **铁律**：代码**禁止折叠**
- **内容**：该场景下的常见错误写法，以及为什么错（行为差异分析）

## 惯用法 vs 语法/API 的区分

| 维度 | 惯用法类 | 语法类 | API 类 |
|------|----------|--------|--------|
| 标题 | "惯用法：XXX" | "语法：XXX" | "API：XXX" |
| 核心内容 | 代码模式 + 适用场景 | 合法/非法写法 | 接口契约 |
| 典型问题 | "这个场景下怎么写最好？" | "这样写合法吗？" | "这个接口的行为边界是什么？" |
| 折叠节 | 完整示例（`[!example]-`） | 无 | 无 |
