# module-intent-writer 专用输出契约

本契约继承通用输出契约，扩展 module-intent-writer 的专用产出规范。

## 产物定义

### 1. 意图文档（主产物）

**文件路径**：
```
docs/功能设计/[所属分组]/[模块编号]-[模块名称]/[模块编号]-[模块名称]-意图文档.md
```

**路径规则**：
- `[所属分组]`：从功能模块全拆解表的章节结构推断（如 `08-AI内容拆解管线`）
- `[模块编号]`：拆解表中的模块编号（如 `M02`）
- `[模块名称]`：拆解表中的模块名称（如 `世界观构建引擎`）

**文件格式**：Markdown，面向业务方和测试人员

**文档状态**：
- `草稿`：s10-intent-generate 生成后的初始状态
- `已冻结`：s11-intent-freeze 获得用户显式授权后的状态

**必须包含的章节**：
1. 项目定位
2. 所属模块与溯源
3. 已有设计兼容性分析
4. 业务目标
5. 用户旅程 / 业务流程
6. 输入/输出业务定义
7. 状态的业务定义（如适用）
8. 异常的业务策略
9. 验收标准
10. 业务依赖关系
11. 业务约束清单
12. 留给规范阶段的技术决策
13. 版本记录（含冻结状态和时间戳）

**内容约束**：
- 使用业务语言，不出现具体技术类型（如 Pydantic、TypeScript 类型）
- 验收标准必须可量化、可测试
- 状态使用业务名称，不含技术转换表
- 所有业务概念使用语义化命名，严禁使用模块编号作为命名前缀
- 必须包含"留给规范阶段的技术决策"章节且内容非空

### 2. 时间戳

文档中的时间戳通过 `scripts/get_timestamp.py` 获取，格式：`YYYY-MM-DD HH:MM:SS`。

## 下游消费

本产物是 **module-spec-writer** 的强制输入。下游 Skill 读取时：
- 以冻结后的意图文档为业务需求基准
- "留给规范阶段的技术决策"章节中的条目需在规范阶段逐一决策
- 验收标准将直接转化为测试用例的验收条件

## 兼容性保证

- 冻结后的意图文档不可擅自修改
- 如需修改，必须通过回退机制解冻后重新冻结
- 版本记录中追加新版本行时，每行必须以 `> ` 开头
