## 执行流程

### 步骤 1：读取并索引所有模块

1. 读取 `功能模块全拆解.md`，提取所有模块条目。
2. 为每个模块建立索引卡片，包含：模块编号、模块名称、模块类型（🔴/🟢）、核心功能、颗粒度描述、所属功能域。
3. 同时读取项目结构设计文档和原始设计文档，理解系统的数据流、分层架构、外部依赖。

### 步骤 2：定义依赖关系类型

分析过程中，识别以下四类依赖：

| 依赖类型 | 符号 | 含义 |
|:---|:---|:---|
| **数据依赖** | ⬅ | 模块 A 的运行需要模块 B 产生的数据/状态。 |
| **调用依赖** | ↗ | 模块 A 直接调用模块 B 的接口、服务或功能。 |
| **时序依赖** | ⏱ | 模块 A 的部署或初始化必须在模块 B 完成后才能进行。 |
| **共享资源依赖** | 🔗 | 两个模块共享同一个数据库表、缓存、配置、第三方服务或消息队列。 |

依赖**强度**分级：
- **强**：缺少被依赖方，依赖方完全无法工作（阻塞性）。
- **中**：缺少被依赖方，依赖方核心功能受损但可降级运行。
- **弱**：缺少被依赖方，依赖方仅部分辅助功能受影响。

### 步骤 3：逐对推断依赖关系

采用两遍扫描策略：

**第一遍 — 显式依赖提取**：
- 从设计文档中直接提取已声明的依赖关系。
- 从项目结构设计文档中提取架构层面的依赖。

**第二遍 — 隐式依赖推断**：
- 基于模块的核心功能和颗粒度描述，推断逻辑上的依赖关系。
- 自问："模块 A 要实现其核心功能，是否需要模块 B 已经就绪？"

**推断依据记录**：每条推断出的依赖都必须记录推断依据，引用源文档的章节。格式：`[文档名] §[章节]` 或 `基于模块描述推断 — [具体理由]`。

### 步骤 4：检测循环依赖

构建依赖有向图后，执行循环依赖检测：
- 如果发现 A → B → C → A 的循环，将其标记为 🔴 循环依赖，并在报告中突出警示。
- 对循环依赖提出打破建议（如引入抽象层、拆分共享数据、事件驱动解耦等）。

### 步骤 5：构建多维输出

#### 5.1 依赖列表

按功能域分组，列出所有被识别出的依赖关系：

```markdown
| 依赖方 | 被依赖方 | 类型 | 强度 | 推断依据 | 确定性 |
|:---|:---|:---|:---|:---|:---|
| ORD-01 订单创建 | PRD-02 商品库存 | ⬅ 数据依赖 | 强 | 设计文档 §4.2 | ✅ 确定 |
```

**确定性标注**：
- ✅ **确定**：源文档明确声明的依赖。
- ⚠️ **推断**：基于模块描述和架构常识推断，无文档直接佐证。
- ❓ **不确定**：推断存在多种可能，需人工确认。

#### 5.2 Mermaid 依赖图

为每个功能域绘制 Mermaid 有向图，并在最后绘制一张全系统汇总图。

Mermaid 语法规范：
- 使用 `graph TD` 或 `graph LR`，根据模块数量选择布局方向。
- 用不同线型区分依赖类型（实线、虚线、粗线、点线）。
- 用 🔴 标注循环依赖节点。
- 当模块数量 >20 时，按功能域拆分为多张子图。

#### 5.3 依赖矩阵

构建 N×N 矩阵（N 为模块总数），行代表依赖方，列代表被依赖方。
若模块数量 >30，按功能域拆分为多个子矩阵，并在最后附一个"功能域间依赖矩阵"（粗粒度）。

#### 5.4 实现分层与并行建议

基于依赖图的拓扑排序，将模块划分为实现层次：

```markdown
| 层级 | 模块 | 可并行度 | 说明 |
|:---|:---|:---:|:---|
| L1（基础层） | INF-01, INF-02, USR-01 | 3 | 无入向依赖，可完全并行开发 |
```

**可并行度** = 该层级包含的模块数。
对 🔴 核心模块，标注其是否为关键路径节点。

### 步骤 6：标记不确定项并给出建议

汇总所有标记为 ⚠️ 推断 和 ❓ 不确定 的依赖项，以表格形式列出：
- 序号、依赖关系、不确定性原因、建议确认的问题。

### 步骤 7：编写输出文档

将以上所有内容整合为一份 Markdown 文档，文件名为 `模块依赖关系分析.md`，保存到与 `功能模块全拆解.md` 相同的目录。

文档结构遵循 `references/output-template.md`。

### 步骤 8：交付前自检

- [ ] 每个模块的编号和名称与 `功能模块全拆解.md` 完全一致。
- [ ] 每条依赖关系都有明确的类型、强度和推断依据。
- [ ] 所有 ⚠️ 推断 和 ❓ 不确定 项都已在不确定项章节中列出。
- [ ] 循环依赖（如有）已被识别并附有打破建议。
- [ ] Mermaid 图语法正确。
- [ ] 依赖矩阵的行列对应关系正确，无错位。
- [ ] 实现分层遵循拓扑排序原则，无层级违反。
- [ ] 🔴 核心模块的关键路径标注已完成。
