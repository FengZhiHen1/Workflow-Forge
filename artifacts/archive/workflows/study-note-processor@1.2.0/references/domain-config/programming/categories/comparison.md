# 对比类原子笔记写作规范 (Comparison Note Specification)

## 适用分类

YAML `type: 对比`，Callout `> [!warning] 对比：[名称]`。

> 对比笔记记录跨语言或跨版本的系统级差异。一般差异应作为语法/语义/API 笔记的子章节；仅在需要系统级横向比较时才独立成篇。

## 独立成篇的判定标准

- 涉及多个知识点的系统性差异（如"Python 2 vs Python 3 的字符串模型"）
- 需要完整的迁移指南（如"从 C++11 迁移到 C++20"）
- 跨语言设计范式对比（如"Rust 所有权 vs C++ 智能指针 vs GC 语言"）

## 各节写作要求

### `> [!warning] 对比：[名称]`
- **内容**：一句话归纳——对比对象 + 核心差异 + 场景建议
- **示例**："Python 2 与 Python 3 的字符串模型对比。核心差异：Python 2 的 `str` 是字节串，`unicode` 是文本；Python 3 的 `str` 是文本（Unicode），`bytes` 是字节串。影响：所有涉及编码/解码的代码都需要重写。"

### `## 对比维度`
- **格式**：表格，横向为对比维度，纵向为对比对象
- **要求**：维度选择要覆盖用户最关心的方面（语法、语义、性能、生态等）

### `## 差异详解`
- **结构**：每个维度一个 `###` 子节
- **内容**：
  - 双方的具体做法（附代码示例）
  - 深层原因（为什么设计成不同？）
  - 对现有代码的影响

### `> [!example]- 代码对比`
- **折叠**：使用 `-` 后缀折叠
- **内容**：同一功能在两种方案中的代码实现对比
- **要求**：代码功能等价，便于读者直观比较

### `## 迁移指南`（如适用）
- **格式**：有序列表 `1. `，按迁移流程编号
- **内容**：
  - 迁移前的检查清单
  - 逐步迁移步骤
  - 迁移后的验证方法

### `> [!warning] 常见迁移陷阱`
- **铁律**：代码**禁止折叠**
- **内容**：迁移过程中最容易踩的坑

### `## 选择建议`
- **用途**：帮助读者决定"我该用哪个？"
- **内容**：不同场景下的推荐方案

## 对比 vs 子章节的区分

| 场景 | 处理方式 |
|------|----------|
| 单个语法点的版本差异 | 作为该语法笔记的 `## 版本演进` 子章节 |
| 单个 API 的跨语言对应 | 作为该 API 笔记的 `## 跨语言对比` 子章节 |
| 多个知识点的系统性差异 | 独立成对比笔记 |
| 完整的技术选型参考 | 独立成对比笔记 |

## 质量检查清单

- [ ] YAML `type` 为 `对比`
- [ ] 首段为 `> [!warning] 对比：[名称]` Callout
- [ ] 对比维度表格覆盖核心差异
- [ ] 差异详解包含"深层原因"分析
- [ ] 代码对比使用 `> [!example]-` 折叠
- [ ] 迁移指南（如适用）步骤清晰
- [ ] 迁移陷阱包含代码示例（不折叠）
- [ ] 选择建议给出明确的场景推荐

- [ ] 代码片段标注环境信息
- [ ] 无编号化名称
