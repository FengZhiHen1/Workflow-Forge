# 语法类原子笔记写作规范 (Syntax Note Specification)

## 适用分类

YAML `type: 语法`，Callout `> [!abstract] 语法：[名称]`。

> 语法笔记记录"怎样写是合法的"，但必须绑定语义上下文，不能孤立记录文法。

## 内容布局（必须按此顺序）

```markdown
---
aliases:
course: {课程名}
type: 语法
status: 待整理
mastery: {1-5}
date_created: YYYY-MM-DD
language: {语言名}
standard: {标准版本}
tags:
  - 编程笔记
---
# {学术描述性名称}

> [!abstract] 语法：{名称}
> 语法规则的精确表述。包括合法形式、非法形式、上下文约束。
> ```{language}
> # env: {语言} {版本} / {实现} / {平台}
> # 核心语法示例（简短片段，不折叠）
> ```

## 运行期语义（可选）

- 该语法在运行期触发什么行为？
- 与编译器/解释器的哪个阶段相关？

## 各节写作要求

### `> [!abstract] 语法：[名称]`
- **位置**：紧接 H1 标题之后，全文第一段正文
- **内容**：语法规则的精确表述。包括：
  - 合法形式的完整描述
  - 明确的非法形式（"以下写法非法：..."）
  - 上下文约束（如"仅在函数体内有效"）
- **代码**：首段必须包含 1 个简短的核心语法示例（fenced code block，不折叠）
- **禁止**：在此 Callout 中混入"为什么这样设计"等非语法内容（放到"理解与细节"）

### `## 运行期语义`（可选）
- **融合条件**：语义可在 3 句话内说清、且仅绑定单一语法点
- **分离条件**：语义涉及多语法点交互，或在多处被引用 → 独立成语义笔记，此处仅留 `- [[独立语义笔记]]`
- **内容**：该语法在词法分析/语法分析/语义分析/代码生成各阶段的行为

### `## 理解与细节`
- **核心价值**：连接抽象语法与直观理解
- **内容要点**：
  - 为什么这样设计？（语法背后的动机）
  - 与读者直觉可能冲突的地方
  - 常见误用（如将 JavaScript 的 `==` 与 `===` 混淆）
  - 编译器/解释器报错信息解读

### `> [!warning] 陷阱`
- **铁律**：陷阱中的代码**禁止折叠**，因为陷阱的价值在于"一眼看到错误"
- **内容**：
  - 错误写法示例（带 `// ❌ 错误：` 注释）
  - 正确写法对比（带 `// ✅ 正确：` 注释）
  - 为什么错？（编译器/解释器的实际行为可能出乎意料）

### `## 版本演进`（可选）
- 仅在语法存在跨版本差异时使用
- 废弃语法：保持 `status: 已整理`，正文中用 `> [!warning]` 标注废弃信息，保留历史参考价值

### `## 关联脉络`
- **上游依赖**：该语法依赖的前置语法概念（如"类语法"依赖"函数语法"）
- **下游推导**：依赖此语法的语义保证、API 接口、惯用法

## 质量检查清单

- [ ] YAML `type` 为 `语法`
- [ ] `language` 和 `standard` 字段已填写
- [ ] 首段为 `> [!abstract] 语法：[名称]` Callout
- [ ] 首段包含核心语法代码示例
- [ ] 理解段包含直观解释和常见误解
- [ ] 陷阱段包含错误代码示例（不折叠）
- [ ] 关联脉络含上下游双链
- [ ] 代码片段标注环境信息（`# env: ...`）
- [ ] 无编号化名称
- [ ] 正文标点使用中文全角
