## 各节写作要求

### `> [!todo] 工具链：[名称]`
- **内容**：一句话归纳——工具名 + 处理对象 + 关键行为
- **示例**："GCC 编译器在 `-O2` 优化级别下的循环优化行为。关键特征：会进行循环展开、常量传播，但可能将某些合法代码优化为未定义行为。"

### `## 适用环境`
- **用途**：工具链行为高度依赖版本和平台，必须明确标注
- **格式**：表格或列表，包含工具版本、平台、关键配置

### `## 工具行为`
- **正常行为**：按工具处理流程分步描述（预处理 → 编译 → 链接 → 运行 等）
- **边界行为**：边界条件下的行为（空输入、极大输入、错误输入等）
- **每步要求**：
  - 清晰描述工具的操作
  - 指出该步骤对源代码的依赖
  - 涉及判定时，明确各分支的结果

### `> [!example]- 完整操作示例`
- **折叠**：使用 `-` 后缀折叠
- **内容**：完整的命令序列及预期输出
- **环境标注**：必须包含 `# env: ...`

### `> [!warning] 陷阱`
- **铁律**：代码/命令**禁止折叠**
- **重点**：
  - 配置错误导致的隐蔽问题
  - 版本差异（"在 X 版本中是 A 行为，在 Y 版本中是 B 行为"）
  - 平台特定限制

## 工具链笔记的必备特征

| 特征 | 说明 |

| 环境绑定 | 必须标注工具版本、平台、配置 |

| 可复现 | 提供完整的命令序列，读者可复现 |
