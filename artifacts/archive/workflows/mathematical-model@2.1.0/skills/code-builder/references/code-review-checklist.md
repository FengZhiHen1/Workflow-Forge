# Reference：代码审查检查清单（Code Review Checklist）

本清单供 code-builder 在代码生成完成后自检使用，也可供 workflow-director 在调度 quality-inspector 前做预审。所有条目必须在交付前逐项确认。

---

## 检查清单使用方式

- 每个检查项标记 `[ ] 待检查` → `[x] 通过` / `[ ] 不适用` / `[ ] 未通过（需说明）`
- 若标记为"未通过"，必须在 Result Report 中给出理由、影响评估和修复计划

---

## A. 与 math-modeler 文档对接检查

### A1 公式编号全覆盖
- [ ] `P3-公式推导_问题建立` 中的所有关键公式（编号公式）在代码中均有对应注释
- [ ] `P3-公式推导_求解算法` 中的所有关键公式在代码中均有对应注释
- [ ] 无遗漏公式（即文档中编号但未在代码中实现的公式）

### A2 变量映射一致性
- [ ] 代码中的变量名与 `P3-符号体系与假设` 中的"代码变量名"列一致
- [ ] 数据读取时的字段名与"数据字段名"列一致
- [ ] 随机变量与确定变量的代码命名区分清晰（如 `X` vs `x`）

### A3 实现约束落实
- [ ] 内存约束已在数据结构中体现（`numpy.ndarray` vs `scipy.sparse`）
- [ ] 精度约束已在数据类型中体现（`float32` vs `float64`）
- [ ] 并行策略已在代码中实现或明确说明为何不启用

### A4 验证标准闭环
- [ ] 验证脚本中的指标与 `P3-验证标准` 中定义的指标一致
- [ ] 阈值与 `P3-验证标准` 中的"可接受阈值"/"优秀阈值"一致
- [ ] 验证脚本输出 `PASS`/`FAIL`/`WARNING` 判定，而非仅输出原始数值

### A5 敏感性分析对接
- [ ] 敏感性分析脚本中的参数列表与 `P3-误差与敏感性分析` 中的敏感参数一致
- [ ] 扰动幅度与 math-modeler 指定的幅度一致（默认 ±10%）
- [ ] 输出格式（CSV + PNG）符合规范

### A6 Toy Model 验证
- [ ] 单元测试中的输入与 `P3-公式推导_问题建立` 中的极简特例一致
- [ ] 单元测试中的预期输出与 math-modeler 的手算结果一致
- [ ] 单元测试已通过（`pytest test_toy_model.py -v` 全绿）

## B. 量纲与单位检查

### B1 单位换算
- [ ] 所有涉及单位换算的数据字段已在 `data_loader.py` 中正确处理
- [ ] 特别注意：km→m、小时→秒、百分比→小数、摄氏度→开尔文等常见陷阱
- [ ] 代码中的常量单位与公式中的量纲一致

### B2 量纲一致性
- [ ] 目标函数/损失函数的量纲与物理意义一致
- [ ] 约束条件的量纲与决策变量的量纲兼容
- [ ] 评估指标的量纲与问题定义一致（如距离用米，不是千米）

---

## C. 边界条件与鲁棒性检查

### C1 边界条件
- [ ] `P3-公式推导_问题建立` 中验证的边界条件在代码中被处理
- [ ] 数组/矩阵索引不越界（特别留意 Python 的 0-based vs 数学的 1-based）
- [ ] 时间/空间离散化的边界点处理与 math-modeler 的约定一致

### C2 除零与数值保护
- [ ] 所有除法分母有 ε 保护（如 `x / (y + 1e-10)`）
- [ ] 所有 `log()` / `log10()` / `ln()` 的参数有 ε 保护
- [ ] 所有 `sqrt()` 的参数非负（或加 `max(x, 0)` 保护）
- [ ] 矩阵求逆/求解处使用 `np.linalg.pinv` 或正则化，而非裸 `np.linalg.inv`

### C3 空值与缺失值
- [ ] 输入数据中的 NaN/Inf 在预处理阶段被处理
- [ ] 缺失值填充策略与 `P3-符号体系与假设` 中声明的一致
- [ ] 分组/聚合操作不会因空组而崩溃

---

## D. 数值稳定性检查

### D1 特征尺度
- [ ] 输入特征量纲差异 > 100 倍时，已做标准化（StandardScaler）或归一化（MinMaxScaler）
- [ ] 标准化参数（均值/方差）在训练集上计算，在测试集上应用

### D2 矩阵病态
- [ ] 条件数 κ 已估算（或已在 math-modeler 中给出）
- [ ] 若 κ > 10⁶，已加正则化（如 ridge λ ≥ 1e-4）或使用截断 SVD
- [ ] 协方差矩阵/海森矩阵不正定时已处理（如加单位矩阵的倍数）

### D3 优化收敛
- [ ] 迭代类算法设置了最大迭代次数（`max_iter`）
- [ ] 设置了收敛容差（`tol`）
- [ ] 记录了损失/目标函数的历史曲线（供 convergence plot 使用）
- [ ] 实现了早停（early stopping）或发散检测

### D4 梯度与溢出
- [ ] 深层网络/复杂迭代中考虑了梯度裁剪（`clip_grad_norm`）
- [ ] 指数增长场景使用了 log 变换（如 `log(x)` 而非 `x`）
- [ ] 大数乘法/幂运算未导致 `inf`（如使用 `logsumexp` 技巧）

## E. 代码质量检查

### E1 可读性
- [ ] 所有函数/类包含 Docstring（参数类型、返回类型、功能描述）
- [ ] 复杂逻辑有行内注释说明"为什么这么做"
- [ ] 公式注释包含原文档中的公式编号（如 `# 公式 (2.3)`）
- [ ] 无死代码、无未使用的导入、无调试用的 `print`（应改用 `logging`）

### E2 模块化
- [ ] 通用功能已提取到 `utils/` 模块（数据加载、指标计算、可视化）
- [ ] 主脚本的核心逻辑可被单元测试直接调用（非全包在 `__main__` 中）
- [ ] 配置参数（文件路径、超参数）与业务逻辑分离（如使用 `argparse` 或配置文件）

### E3 错误处理
- [ ] 业务逻辑中的异常使用 try/except 捕获并给出 meaningful error message
- [ ] **import 阶段无 try/except ImportError**（必须让导入失败直接暴露）
- [ ] 关键步骤的失败会终止程序并返回非零退出码（`sys.exit(1)`）

### E4 命名规范
- [ ] 函数名、变量名、类名、文件名均为英文，无中文
- [ ] 命名风格一致（snake_case 用于函数/变量，CamelCase 用于类）
- [ ] 常量使用 UPPER_SNAKE_CASE

## F. 可视化规范检查

### F1 基础规范
- [ ] 所有输出图片分辨率 ≥ 300 dpi
- [ ] 坐标轴标签字号 ≥ 10pt，图例字号 ≥ 9pt
- [ ] 单栏图宽度 ≈ 8.5 cm（3.35 英寸），双栏图宽度 ≈ 17 cm（6.69 英寸）
- [ ] 图片无多余白边（使用 `bbox_inches="tight"`）

### F2 命名与组织
- [ ] 图片命名格式为 `fig_{NN}_{description}.png`
- [ ] 所有图片保存到 `VERSION_RESULTS/exp_{NN}_{scheme}/png/` 或 `comparison/png/`
- [ ] 图片数量与可视化规划一致，无遗漏

### F3 图表完整性
- [ ] 所有图表均有坐标轴标签（含单位）
- [ ] 所有图表均有标题或图注说明
- [ ] 多线图中均有图例，且图例位置不遮挡数据
- [ ] 颜色选择对色盲友好（避免红绿对比）

### F4 必须图表（依模型类型勾选）
- [ ] 迭代/优化类算法：**收敛曲线**（损失/目标函数 vs 迭代次数）
- [ ] 统计/回归模型：**残差 QQ 图**、**残差直方图**、**预测 vs 实际散点图**
- [ ] 敏感性分析：**龙卷风图**（Tornado diagram）
- [ ] 时间序列模型：**预测曲线 vs 实际曲线**
- [ ] 分类模型：**ROC 曲线**、**混淆矩阵热力图**
- [ ] 所有模型：**关键结果展示图**（依问题自定义）

## H. 错误恢复与降级检查

### H1 降级路径
- [ ] 代码中已实现 math-modeler 指定的至少 1 条降级路径（如正则化开关、简化模型分支）
- [ ] 降级路径可通过参数或配置文件触发，无需改代码

### H2 常见错误处理
- [ ] OOM：已实现分批计算或稀疏矩阵降级
- [ ] 超时：已实现超时装饰器或最大迭代限制
- [ ] 数据缺失：已实现代理变量或跳过策略
- [ ] 矩阵奇异：已实现伪逆或正则化保护
