# Reference：审查检查清单（Review Checklist）

本清单供 quality-inspector 自检使用，也可供 workflow-director 在调度前做预审。所有条目必须在交付前逐项确认。

---

## 检查清单使用方式

- 每个检查项标记 `[ ] 待检查` → `[x] 通过` / `[ ] 不适用` / `[ ] 未通过（需说明）`
- 若标记为"未通过"，必须在对应文档中给出理由和影响评估

---

## A. 验证报告审查清单

### A1 指标计算正确性
- [ ] 至少抽查了 2 个指标的手算复核
- [ ] 抽查偏差 < 5%（或已在文档中说明偏差原因）
- [ ] 抽查的指标覆盖了核心性能指标（如 R²、RMSE、MAPE）

### A2 阈值使用正确性
- [ ] 对照了 `P3-验证标准_[model].md` 中的阈值
- [ ] 确认了 PASS/FAIL 判定逻辑正确（注意：R² 越大越好，RMSE 越小越好）
- [ ] 发现了阈值使用错误（如有）并在文档中标注

### A3 残差分析规范性
- [ ] QQ 图已生成且检验方法正确
- [ ] 残差直方图已生成
- [ ] 残差-拟合值散点图已生成
- [ ] 残差检验方法（Shapiro-Wilk / KS）选择合理

### A4 报告一致性
- [ ] `validation_report.md` 中的数值与 `evaluation_metrics.csv` 完全一致
- [ ] 发现了不一致（如有）并在文档中标注

---

## B. 假设统计反向验证清单

### B1 检验方法选择
- [ ] 根据模型类型选择了正确的检验方法（回归/时间序列/分类）
- [ ] 所有适用的 P0 级假设均执行了统计检验
- [ ] 样本量满足检验方法的要求（如 Shapiro-Wilk 适用于 n < 5000）

### B2 检验结果记录
- [ ] 每项检验记录了统计量和 p 值
- [ ] 未通过的 P0 假设已在评估报告中重点标注
- [ ] 未通过的 P1 假设已记录为风险提示

### B3 检验工具
- [ ] 使用了 Python 标准库或 scipy/statsmodels 执行检验
- [ ] 检验代码可复现（随机种子固定，如适用）

---

## C. 敏感性分析结果审查清单

### C1 参数排序一致性
- [ ] 读取了 math-modeler 的 `P3-误差与敏感性分析` 中的预期排序
- [ ] 读取了 code-implementer 的 `sensitivity_matrix.csv`
- [ ] 对比了参数排序是否一致

### C2 数量级一致性
- [ ] 对比了 math-modeler 的理论预期值与 code-implementer 的实际值
- [ ] 偏差在同一数量级内（< 50%）或可解释

### C3 异常分析
- [ ] 排序不一致或数量级偏差大的参数已做异常分析
- [ ] 给出了可能原因：代码实现错误 / 数值精度 / 理论假设不成立

---

## D. 代码质量轻量审查清单

### D1 公式对应性
- [ ] 随机抽查了 3–5 个核心公式编号
- [ ] 代码注释与公式编号对应
- [ ] 实现逻辑与公式推导一致

### D2 边界条件
- [ ] 检查了 `test_toy_model.py` 是否覆盖了 math-modeler 验证的边界条件
- [ ] 发现了未覆盖的边界条件（如有）并在文档中标注

### D3 数值稳定性
- [ ] 检查了正则化参数是否在合理范围
- [ ] 检查了 ε 保护是否存在且合理
- [ ] 检查了梯度裁剪（如适用）是否合理

### D4 路径规范
- [ ] 检查了代码是否使用 `__file__` 推导路径
- [ ] 发现了基于 `os.getcwd()` 的路径写法（如有）并在文档中标注

---

## E. 可视化结果审查清单

### E1 完整性
- [ ] 检查了赛题要求的所有图表类型是否都已生成
- [ ] 发现了遗漏的图表（如有）并在文档中标注

### E2 规范性
- [ ] 抽查了至少 3 张图表的分辨率（≥ 300 dpi）
- [ ] 抽查了坐标轴标签字号（≥ 10pt）
- [ ] 抽查了图例字号（≥ 9pt）
- [ ] 抽查了图片尺寸（单栏 8.5cm / 双栏 17cm）

### E3 无误导性
- [ ] 检查了是否存在 Y 轴截断夸大差异的情况
- [ ] 检查了双 Y 轴图表是否合理
- [ ] 检查了颜色选择是否色盲友好

### E4 与正文一致性
- [ ] 对比了正文描述与图表数据
- [ ] 发现了不一致（如有）并在文档中标注

---

## F. 赛题覆盖度检查清单

### F1 问题拆解
- [ ] 将赛题原文拆解为原子需求（不可再分）
- [ ] 每个原子需求都有明确的"是/否"判定

### F2 覆盖检查
- [ ] 逐项核对了原子需求与实际模型输出
- [ ] 每个原子需求都标注了对应文件/图表路径

### F3 遗漏分级
- [ ] 所有未覆盖项已按 P0/P1/P2 分级
- [ ] P0 遗漏项不超过 0 个（否则判定为 BLOCKED）

### F4 判定依据
- [ ] 判定基于赛题原文，而非主观印象
- [ ] 引用了具体的赛题原文段落作为依据

---

## G. 跨方案对比清单（若适用）

### G1 数据完整性
- [ ] 读取了 model-architect 的 `P2-模型选型_对比总结.md`
- [ ] 读取了所有实验目录（`exp_01/`、`exp_02/` 等）的结果

### G2 对比分析
- [ ] 对比了预期 vs 实际在每个维度上的表现
- [ ] 偏差分析有具体数值支撑

### G3 推荐判定
- [ ] 给出了明确的最终推荐（维持或修正）
- [ ] 推荐有充分的数值依据
- [ ] 给出了切换条件（何时降级/升级）

## H. 四维度评分自检

### H1 评分依据
- [ ] 每个维度的得分都有明确的数值依据
- [ ] 评分标准与 `P3-验证标准` 一致

### H2 权重应用
- [ ] 加权总分计算正确
- [ ] 各维度权重之和为 100%

### H3 迭代回路判定
- [ ] 总分和 P0 假设结果共同决定了迭代回路判定
- [ ] 判定与迭代回路触发规则表一致
