# Reference：验证检查清单（Validation Checklist）

本清单供 math-modeler 自检使用，也可供 workflow-director 在调度 quality-inspector 前做预审。所有条目必须在产出交付前逐项确认。

---

## 检查清单使用方式

- 每个检查项标记 `[ ] 待检查` → `[x] 通过` / `[ ] 不适用` / `[ ] 未通过（需说明）`
- 若标记为"未通过"，必须在对应文档中给出理由和风险评估

---

## A. 符号体系检查

### A1 完整性
- [ ] 所有在公式中出现的符号均在符号表中定义
- [ ] 符号表中无重复定义或歧义
- [ ] 下标/上标的使用方式在文档中统一说明

### A2 严谨性
- [ ] 随机变量与确定变量已区分标记（大写 vs 小写）
- [ ] 所有向量/矩阵在首次出现时声明了维数（如 $\mathbf{X} \in \mathbb{R}^{n \times p}$）
- [ ] 索引基约定已明确（从 0 还是从 1 开始）
- [ ] 时间连续变量 $t$ 与时间离散索引 $k$ 未混用

### A3 工程兼容性
- [ ] 所有希腊字母符号均给出了对应的代码变量名（如 $\alpha$ → `alpha`）
- [ ] 代码变量名符合常用命名规范（snake_case 或 camelCase），无歧义
- [ ] 下标在代码中用 underscore 表示时不会产生冲突（如 $x_{i,j}$ → `x[i,j]`）

---

## B. 公式推导检查

### B1 逻辑完备性
- [ ] 从问题定义到最终公式的每一步都有推导依据（定义/引理/假设/已知条件）
- [ ] 不存在"显然可得"或"易知"等无依据的跳跃
- [ ] 关键公式已编号（如公式 2.1、2.2），且编号在全文中唯一

### B2 数学正确性
- [ ] 所有等式两边的量纲一致
- [ ] 不等式方向在变换过程中保持正确（乘以负数时方向翻转）
- [ ] 积分/求和上下限正确，变量未与积分变量混淆
- [ ] 概率表达式满足 $0 \leq P \leq 1$，方差满足 $\sigma^2 \geq 0$

### B3 边界与极限
- [ ] 边界条件已验证（至少 2 个典型边界）
- [ ] 至少完成了 1 个极端情形测试（参数趋于 0 或 $\infty$）
- [ ] 极限结果符合物理/数学直觉

### B4 Toy Model 验证
- [ ] 已构造至少 1 个可手算的极简特例（$n \leq 3$ 或 $T \leq 2$）
- [ ] Toy Model 的手算结果与直觉一致
- [ ] Toy Model 的结果已记录，供 code-implementer 做单元测试基准

---

## C. 假设评估检查

### C1 显性假设
- [ ] 所有在推导中明确使用的假设均经过五维评估
- [ ] 每个假设给出了合理性评级及支撑证据
- [ ] 每个假设的必要性已判断（核心假设 vs 辅助假设）
- [ ] 每个假设的失效条件已明确

### C2 隐式假设
- [ ] 至少挖掘了 2 个隐式假设（题目未明说但推导默认成立）
- [ ] 隐式假设同样经过了五维评估

### C3 优先级与退化
- [ ] 所有假设已按 P0/P1/P2 分级
- [ ] P0 级假设均给出了替代方案或退化路径
- [ ] 退化路径与 model-architect 的备选方案建立了对应关系

---

## D. 可解性与数值分析检查

### D1 问题类别
- [ ] 已判定问题类别（凸优化/非凸优化/ODE/PDE/组合优化/其他）
- [ ] 已判断解析解是否存在
- [ ] 若为非凸/非线性，已说明局部最优与全局最优的风险

### D2 复杂度
- [ ] 时间复杂度上界已给出（至少是大 O 记号）
- [ ] 空间复杂度上界已给出
- [ ] 若问题为 NP-hard，已说明近似比或启发式策略

### D3 数值方法
- [ ] 至少给出了 2 种候选数值方法
- [ ] 对每种方法说明了适用条件、收敛阶、优缺点
- [ ] 给出了最终推荐方法及理由

### D4 收敛与稳定
- [ ] 收敛性条件已给出（如步长限制、Lipschitz 条件）
- [ ] 迭代终止准则已明确（如残差 $< 10^{-6}$ 或相对变化 $< 10^{-4}$）
- [ ] 初值敏感性已评估

### D5 资源预估
- [ ] 单次求解耗时已估算（单位：秒）
- [ ] 内存峰值已估算（单位：GB）
- [ ] 预估基于具体模型规模（$n, p, T$ 等），而非空泛声明

---

## E. 误差分析检查

### E1 误差预算
- [ ] 至少识别了 3 类误差来源（模型简化、数值离散、数据噪声）
- [ ] 每类误差给出了估计量级（至少定性，如"主导"/"次要"/"可忽略"）
- [ ] 给出了控制每类误差的方法或策略

### E2 敏感性
- [ ] 参数敏感性矩阵已计算（解析或数值）
- [ ] 敏感参数与钝感参数已区分
- [ ] 参数标定优先级已给出（先标定敏感参数）

### E3 结构敏感性
- [ ] 至少分析了 1 个核心假设放松后的模型退化路径
- [ ] 退化路径与 model-architect 的备选方案建立了对应

---

## F. 数据映射检查

### F1 映射完整性
- [ ] 所有数学符号均映射到了代码变量名和数据字段名
- [ ] 无遗漏字段（即公式中出现但映射表中缺失的符号）
- [ ] 不参与建模的冗余字段已明确说明

### F2 数据质量
- [ ] 最小样本量已估算并与实际样本量对比
- [ ] 信噪比已估计或定性判断
- [ ] 多重共线性/条件数已评估
- [ ] 缺失模式（MCAR/MAR/MNAR）已判断

### F3 实现约束
- [ ] 每个符号均标注了实现约束（存储方式、内存限制、精度要求等）
- [ ] 实现约束对 code-implementer 有实际指导意义

---

## G. 验证标准检查

### G1 指标完整性
- [ ] 至少定义了 2 个拟合/预测性能指标及计算公式
- [ ] 每个指标给出了"可接受"和"优秀"两级阈值

### G2 残差检验
- [ ] 残差分布假设已声明（通常为正态）
- [ ] 检验方法及通过阈值已明确

### G3 计算性能
- [ ] 单次求解耗时阈值已设定
- [ ] 内存占用阈值已设定

### G4 Toy Model 闭环
- [ ] Toy Model 的手算结果已记录
- [ ] 数值实现后的结果与手算结果的偏差已计算
- [ ] 偏差在可接受范围内（或已说明原因）

---

## H. 文件结构与命名合规检查

### H1 文件拆分
- [ ] 产出已按规范拆分为 **至少 3 个、至多 5 个** 独立文件（严禁合并为单个文件）
- [ ] 每个文件仅包含对应模板规定的内容类别，无交叉冗余
- [ ] 文件总数 ≤ 5（防止过度碎片化）

### H2 命名合规
- [ ] 所有文件名遵循 `P3-{类别}_[model].md` 格式
- [ ] `[model]` 值与 Task Package 中 `naming_constraint` 或 `selected_scheme` 一致
- [ ] 无自定义命名（如 `Task1_聚合ILP` 等非规范命名）

### H3 交叉引用完整性
- [ ] `P3-符号体系与假设` 文件包含版本记录表
- [ ] 其他文件通过一句话引用符号定义来源，而非重复定义
- [ ] 文件间的交叉引用路径准确可解析

---

## I. 数据一致性检查

### I1 与上游文档一致性（致命级）
- [ ] 所有从 P2 引用的参数数值与 P2-模型选型报告**逐字一致**
- [ ] 所有从 P1b 引用的需求数据与 P1b-小问分析 / data-scout 报告**逐字一致**
- [ ] 每个引用参数均标注了来源文档和具体位置（如 `[P2-模型选型_方案01_聚合ILP.md 第 X 节]`）
- [ ] 已核对：P2 中参数的**数学定义**与 P3 中的**理解**完全一致（不仅是数值一致）

### I2 跨文件内部一致性（致命级）
- [ ] 同一符号/参数在 `P3-符号体系与假设`、`P3-公式推导_问题建立`、`P3-公式推导_求解算法` 中的数值完全一致
- [ ] 同一符号/参数在多个 P3 文件中的数学定义完全一致
- [ ] 下界、汇总值等推导结果与原始数据计算结果一致

### I3 数据引用规范
- [ ] 不存在凭记忆手动转写的数值（必须从源文档复制粘贴）
- [ ] 不存在"显然"或"易知"等无来源的数值声明
- [ ] 新引入的符号/参数在首次出现时明确说明了定义来源

---

## 最终确认

- [ ] 所有 `[ ] 未通过` 项已在对应文档中给出理由和风险评估
- [ ] 所有文档的 naming_constraint 一致
- [ ] 所有产出位于 Task Package 指定的 `target_dir` 内
- [ ] 已清理临时文件，仅保留目标产出文档
