# 全局目录结构约定

> 本文件为工作流级共享规范。所有 `project-design-pipeline@2.0.0` 的 Skill 均需遵守。
> 定义 `docs/` 目录下各产物的路径、命名规则和用途。

---

## 1. 项目顶层目录

| 目录 | 用途 | 说明 |
|------|------|------|
| `docs/` | 设计文档主目录 | 所有阶段产物的最终落盘位置 |
| `contracts/` | 通用契约 | Skill 级可选的输入/输出契约 |
| `references/` | 工作流级共享参考 | agent-protocol.md、directory-convention.md 等 |
| `scripts/` | 基础设施脚本 | write_message.py、get_timestamp.py 等 |

---

| 文件 | 产生 Stage | 说明 |

## 3. docs/功能设计/ 子目录

### 3.1 项目级分析文档

| 文件 | 产生 Stage | 说明 |
|------|-----------|------|
| `docs/功能设计/功能模块全拆解.md` | s04-module-breakdown | 所有功能模块的登记与分类 |
| `docs/功能设计/模块依赖关系分析.md` | s05-dependency-analysis | 模块间依赖关系、Mermaid 图、依赖矩阵 |
| `docs/功能设计/_sync-issues.md` | 各模块 Stage（按需） | 项目级设计矛盾追踪 |

### 3.2 单模块文档目录

每个功能模块在独立子目录下产生三份文档：

```
docs/功能设计/[序号]-[分组]/[编号]-[名称]/
  ├── [编号]-[名称]-意图文档.md
  ├── [编号]-[名称]-设计文档.md
  └── [编号]-[名称]-落地规范.md
```

**命名约定**：
- 序号格式：`01`、`02`（两位数字，决定分组目录的排列顺序）
- 分组：中文，反映模块的业务归属
- 编号：**必须严格使用 `docs/功能设计/功能模块全拆解.md` 中分配给该模块的编号**（如 `M01`、`M02`），不得自行编造或修改。该编号是跨文档引用模块的唯一定位符
- 名称：中文，与全拆解文档中登记的名称一致

**示例**：
```
docs/功能设计/01-用户域/M01-订单系统/
docs/功能设计/01-用户域/M02-支付网关/
docs/功能设计/02-商品域/M03-库存管理/
```

---

## 4. 临时文件

Agent 运行时的中间产物写入 `.tmp/<workflow_instance_id>/`，不在 `docs/` 下留痕迹。

临时文件命名使用 kebab-case（如 `requirements-context.md`、`architecture-decisions.md`）。
