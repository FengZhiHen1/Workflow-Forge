# Reference：约束类型分类与转化框架

本文件提供数学建模竞赛中常见约束类型的系统化分类。在 P1b 小问分析阶段，用于扫描题意中的隐含约束，确保不遗漏关键建模要素。

---

## 约束类型总览

| 类型编号 | 类型名称 | 常见自然语言信号 | 数学表达通式 | 数模出现频率 |
|:---|:---|:---|:---|:---|
| C01 | 等式约束 | "总量守恒""收支平衡""等于""恰好" | $f(x) = C$ 或 $g(x,y) = h(x,y)$ | 高 |
| C02 | 不等式约束 | "不超过""至少""容量限制""不大于" | $f(x) \leq C$ 或 $f(x) \geq C$ | 高 |
| C03 | 整数约束 | "必须为整数""整数个""0-1 决策""是否" | $x_i \in \mathbb{Z}$ 或 $x_i \in \{0,1\}$ | 中高 |
| C04 | 互斥约束 | "不能同时""二者择一""排他性""至多选一个" | $x_i + x_j \leq 1$（二进制）或 $\sum_{i \in S} x_i \leq 1$ | 中 |
| C05 | 逻辑约束 | "若 A 则 B""只有...才...""顺序依赖""优先级" | $x_A \leq x_B$ 或 $x_A = 1 \Rightarrow x_B = 1$ | 中 |
| C06 | 概率/风险约束 | "置信度不低于""风险阈值""概率不超过""以...的把握" | $P(X \leq T) \geq \alpha$ 或 $\text{VaR}_\alpha(X) \leq V$ | 中低 |
| C07 | 动态/递推约束 | "状态转移""递推关系""演化规律""下一时刻" | $s_{t+1} = f(s_t, a_t)$ 或 $x_{t+1} = g(x_t, u_t)$ | 中 |
| C08 | 边界/初终值条件 | "初始值为""边界处为""起始状态""终点要求" | $x(0) = x_0$ 或 $x(T) = x_T$ 或 $\frac{\partial u}{\partial n}\big|_{\Gamma} = 0$ | 中 |

## 各类型详细说明与示例

### C01 等式约束

**典型场景**：
- 资源分配：总分配量等于总资源量
- 质量守恒：输入质量 = 输出质量 + 损耗
- 定义式：某指标由其他指标定义

**自然语言信号词**：
> "恰好分配完毕""总量保持不变""收支平衡""满足守恒定律""由...定义"

**数学表达示例**：
- 资源分配：$\sum_{i=1}^{n} x_i = Q$，其中 $Q$ 为总资源量
- 质量守恒：$m_{\text{in}} = m_{\text{out}} + m_{\text{loss}}$
- 定义式：$y_i = \frac{a_i}{\sum_j a_j}$

**建模注意**：
- 等式约束过强可能导致可行域退化甚至为空，需检查一致性
- 多个等式约束可能隐式消除变量，降低模型维度

---

### C02 不等式约束

**典型场景**：
- 容量限制：仓库容量、预算上限
- 最低要求：至少满足...、不低于...
- 安全边界：温度不超过...、压力不低于...

**自然语言信号词**：
> "不超过""不大于""不超过...的上限""至少""不小于""不低于...的下限""在...范围内""容量为..."

**数学表达示例**：
- 容量：$\sum_{i} w_i x_i \leq W_{\max}$
- 预算：$\sum_{i} c_i x_i \leq B$
- 范围：$L_i \leq x_i \leq U_i$

**建模注意**：
- 注意严格不等式 $>$ vs 非严格不等式 $\geq$ 在优化中的处理差异
- 上下界约束常可合并为盒约束 $L \leq x \leq U$

---

### C03 整数约束

**典型场景**：
- 计数问题：设备台数、人员数量
- 0-1 决策：是否选址、是否执行某方案
- 离散选择：从有限选项中选择

**自然语言信号词**：
> "整数个""必须为整数""是否""选择/不选择""开关""0 或 1""二进制决策"

**数学表达示例**：
- 整数：$x_i \in \mathbb{Z}^+$
- 0-1：$x_i \in \{0, 1\}$
- 多选一：$\sum_{i} y_i = 1,\; y_i \in \{0,1\}$

**建模注意**：
- 整数约束使问题从 LP 变为 MILP/INLP，计算复杂度显著上升
- 大规模整数问题在竞赛时间内可能不可解，需评估问题规模
- 可考虑松弛为连续变量后取整，或使用启发式算法

---

### C04 互斥约束

**典型场景**：
- 排他性选择：同一位置不能同时建两种设施
- 时间冲突：同一时段不能安排两个任务
- 资源独占：同一设备不能同时加工两个工件

**自然语言信号词**：
> "不能同时""二者择一""排他性""至多选一个""互斥""冲突""不能共存"

**数学表达示例**：
- 二元互斥：$x_i + x_j \leq 1,\; x_i, x_j \in \{0,1\}$
- 多选互斥：$\sum_{i \in S} x_i \leq 1$
- 条件互斥：若 $x_i = 1$ 则 $x_j = 0$：$x_i + x_j \leq 1$

**建模注意**：
- 互斥约束通常与整数约束配合使用
- 大量互斥约束可能导致可行域碎片化

---

### C05 逻辑约束

**典型场景**：
- 条件依赖：如果选择 A 则必须选择 B
- 顺序约束：任务 A 必须在任务 B 之前完成
- 优先级：高优先级任务优先分配资源

**自然语言信号词**：
> "若...则...""如果...那么...""只有...才...""在...之后""先于...""优先级""依赖"

**数学表达示例**：
- 蕴含：$x_A = 1 \Rightarrow x_B = 1$ → $x_A \leq x_B$（当 $x_B \in \{0,1\}$）
- 顺序：$t_j \geq t_i + d_i$（任务 $j$ 在任务 $i$ 完成后开始）
- 双向：$x_A = 1 \Leftrightarrow x_B = 1$ → $x_A = x_B$

**建模注意**：
- 逻辑约束的线性化需要引入辅助变量和大 M 方法
- 注意 $M$ 的取值：过大导致数值不稳定，过小导致约束无效

---

### C06 概率/风险约束

**典型场景**：
- 可靠性要求：系统失效概率不超过...
- 置信度要求：以 95% 的把握保证...
- 风险限制：VaR/CVaR 不超过...

**自然语言信号词**：
> "置信度""概率""风险""可靠性""以...的把握""不超过...的概率""安全概率"

**数学表达示例**：
- 概率约束：$P(g(x, \xi) \leq 0) \geq \alpha$
- VaR 约束：$\text{VaR}_\alpha(X) \leq V$
- 期望约束：$E[f(x, \xi)] \leq C$

**建模注意**：
- 概率约束通常需要随机规划或鲁棒优化处理
- 若数据为确定性数据，概率约束可退化为最坏情况分析
- 竞赛中若缺乏概率分布信息，常用情景分析法或蒙特卡洛模拟

---

### C07 动态/递推约束

**典型场景**：
- 状态转移：系统随时间/空间演化
- 递推关系：斐波那契式、马尔可夫式
- 差分方程：离散时间动力学

**自然语言信号词**：
> "状态转移""递推""演化""下一时刻""下一状态""随时间变化""动态过程""迭代"

**数学表达示例**：
- 离散状态转移：$s_{t+1} = f(s_t, a_t)$
- 线性递推：$x_{t+1} = A x_t + B u_t$
- 差分方程：$\Delta x_t = g(x_t, t)$

**建模注意**：
- 需明确时间/空间步长、状态维度、控制维度
- 初值条件（C08）通常与动态约束配套出现
- 连续时间问题可能需要离散化处理

---

### C08 边界/初终值条件

**典型场景**：
- 初始状态：系统起始状态已知
- 边界条件：区域边界上的约束
- 终值目标：到达某状态或区域

**自然语言信号词**：
> "初始值为""起始状态""在...时刻为""边界处""终值""终点要求""在 $t=0$ 时"

**数学表达示例**：
- 初值：$x(0) = x_0$
- 终值：$x(T) = x_T$
- 边界：$u|_{\Gamma} = u_0$ 或 $\frac{\partial u}{\partial n}\big|_{\Gamma} = 0$

**建模注意**：
- 初值+动态约束构成初值问题（IVP）
- 边界+动态约束构成边值问题（BVP）
- 注意边值问题的适定性（解的存在唯一性）

## 使用指南

在 P1b 小问分析阶段，按以下流程扫描约束：

1. **通读题目原文**，标记所有含信号词的句子
2. **逐句判断约束类型**（C01-C08），填写到小问分析的"特殊机制与约束"章节
3. **检查遗漏**：
   - 是否有"显然成立"但未明确写出的约束？（如自然数约束）
   - 是否有多个小问共用但未在单个小问中重复的约束？
   - 约束之间是否自洽？（等式约束是否过约束？）
4. **标注约束强度**：硬约束（必须满足）/ 软约束（尽量满足，可转化为惩罚项）
