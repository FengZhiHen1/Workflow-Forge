## 三、模块联动审查

### 3.1 预期联动关系（来自设计文档）

```
M01(用户认证) ──token──> M03(订单处理) ──状态更新──> M05(通知服务)
     ^                      ^
     └───── 用户ID校验 ──────┘
```

### 3.2 实际联动验证

| 联动路径 | 设计描述 | 实际代码证据 | 状态 | 备注 |
|----------|----------|--------------|------|------|
| M01 → M03 | M03 调用 M01 的 `verify_token()` 校验用户 | `src/order/api.py:15` import `auth.verify_token` | ✅ 已实现 | - |
| M03 → M05 | M03 在订单状态变更时调用 M05 的 `send_notification()` | 未找到 M03 中调用 M05 的代码 | ❌ 未实现 | - |
| M03 → M05(数据) | 传递 `{order_id, status, timestamp}` | 无对应数据结构定义 | ❌ 未实现 | - |

### 3.3 联动问题详情

- 🔴 **M03 → M05 联动缺失**：设计文档要求订单完成后通知用户，但 M03 的 `processor.py` 完成订单处理后未调用任何通知接口。建议：在 `process_order()` 完成后调用 `notification.send_order_update(order_id, status)`。
