# Pattern Matcher Pack — 工作流模式识别与套用

> 当需要快速设计工作流、或判断当前需求最适合哪种常见模式时，加载此包。
>
> **需要完整 YAML 模板时**，读取 `references/workflow-patterns.md`（本包内参考文件）。

## 常见工作流模式

### 1. 顺序审批流

```
s00 → s01(分析) → s02(评审/确认) → s03(执行) → s99
```

- 特征：单向顺序执行，中间有 1-2 个确认点
- 适用：简单任务、单 Skill 改造、标准审批流程
- 变体：可在 s02 后加迭代循环（confirm + continue自循环）

### 2. 并行分支流

```
s00 → s01(分发) → [s02-a, s02-b, s02-c](并行) → s03(聚合) → s99
```

- 特征：一个 Stage 产出多个目标，下游并行执行，最后聚合
- 适用：多模块同步处理、批量任务
- 关键：s01 如需用户交互，使用 AskUserQuestion + confirm + continue

### 3. 迭代打磨流

```
s00 → s01(初稿) → s01(confirm + continue:继续完善) → s01(confirm + continue:继续完善) → s02(终稿确认) → s99
                ↓
              s99(放弃)
```

- 特征：同一个 Stage 自循环多次，逐步完善产出
- 适用：需要多轮用户反馈的场景（设计、写作、方案）
- 关键：必须配 `max_loop` + `loop_exceeded` 出口

### 4. 条件路由流

```
s00 → s01(分析判定) → s02(路径A) → s04(汇聚) → s99
               ↘ s03(路径B) ↗
```

- 特征：s01 根据分析结果自动选择下游路径（success + choice）
- 适用：根据输入特征走不同处理分支
- 关键：choice 值清晰、汇聚点明确

### 5. 流水线流

```
s00 → s01(提取) → s02(转换) → s03(验证) → s04(输出) → s99
```

- 特征：纯数据流，无确认点，Stage 间严格顺序
- 适用：ETL、格式转换、纯自动化任务
- 关键：每个 Stage 都要有 failure 路径

### 6. 探索-决策-执行流

```
s00 → s01(探索/信息收集) → s02(分析+确认) → s03(执行) → s99
```

- 特征：先收集信息，再用户决策，最后执行
- 适用：需要用户基于信息做判断的复杂任务
- 关键：s01 无确认点（只是收集），s02 有确认点（决策点）

## 模式套用方法

1. **识别需求特征**：用户输入、确认点数量、并行可能性、失败处理需求
2. **匹配最接近的模式**：选择结构上最相似的模式作为起点
3. **调整**：根据具体需求增减 Stage、调整 edges、添加确认点
4. **混合模式**：允许组合多种模式，但汇聚点必须清晰

## 快速设计策略

- 简单场景（单 Skill、≤2 确认点）：套用顺序审批流或流水线流
- 需要用户多轮反馈：套用迭代打磨流
- 多模块独立处理：套用并行分支流
- 根据输入走不同分支：套用条件路由流
- 复杂场景：组合多种模式
