# 常见模块联动模式参考

本文件列举常见的模块间联动模式及对应的代码验证方法，供审查时参考。

---

## 模式 1：同步调用（Direct Call）

**描述**：模块 A 直接调用模块 B 的函数/方法。

**设计文档典型描述**：
> "M03 调用 M01 的 `verify_token()` 进行用户认证"

**代码验证方法**：
- 在模块 A 的代码中搜索 `from module_b import` 或 `import module_b`
- 搜索被调用的函数名是否出现在模块 A 中
- 检查调用点的参数列表是否与模块 B 的函数签名匹配

**示例证据**：
```python
# src/order/api.py (M03)
from src.auth.jwt_handler import verify_token  # ✅ 联动证据

@router.post("/orders")
def create_order(token: str, ...):
    user = verify_token(token)  # ✅ 调用证据
```

---

## 模式 2：事件/消息传递（Event Driven）

**描述**：模块 A 发布事件，模块 B 订阅并处理。

**设计文档典型描述**：
> "M03 在订单状态变更时发送 `OrderStatusChanged` 事件，M05 订阅该事件并发送通知"

**代码验证方法**：
- 在模块 A 中搜索 `emit`、`publish`、`dispatch`、`post` 等事件发送关键字
- 在模块 B 中搜索 `on`、`subscribe`、`listen`、`handle` 等事件接收关键字
- 检查事件名/主题名是否一致
- 检查事件数据结构（payload）是否匹配

**示例证据**：
```python
# M03 发送端
event_bus.emit("order.status_changed", {"order_id": oid, "status": "completed"})

# M05 接收端
@event_bus.on("order.status_changed")  # ✅ 主题名一致
def handle_status_change(payload):
    ...
```

---

## 模式 3：数据流/管道（Data Pipeline）

**描述**：模块 A 的输出数据作为模块 B 的输入数据。

**设计文档典型描述**：
> "M02 生成的报表数据传入 M04 进行可视化渲染"

**代码验证方法**：
- 对比模块 A 的输出数据结构（return type / DTO）与模块 B 的输入参数类型
- 检查是否存在数据转换/适配层
- 检查数据传递方式（函数参数、共享内存、文件、数据库等）

---

## 模式 4：数据库/存储共享（Shared State）

**描述**：多个模块读写同一张表/同一个存储键。

**设计文档典型描述**：
> "M01 写入用户表，M03 读取用户表获取收货地址"

**代码验证方法**：
- 检查模块 A 和模块 B 的 ORM 模型是否指向同一张表
- 检查 SQL 语句中的表名是否一致
- 检查读写字段是否存在（模块 B 读模块 A 写入的字段）

---

## 模式 5：HTTP/API 调用（Service Call）

**描述**：模块 A 通过 HTTP 请求调用模块 B 提供的 API。

**设计文档典型描述**：
> "M05 通过 REST API 调用 M06 的短信发送接口"

**代码验证方法**：
- 在模块 A 中搜索 `requests.get/post`、axios、`fetch` 等 HTTP 调用
- 检查 URL 路径是否与模块 B 的路由定义匹配
- 检查请求体/查询参数与模块 B 的 API 文档是否一致
- 检查响应处理逻辑是否与模块 B 的返回结构匹配

---

## 模式 6：依赖注入/服务定位（DI/Service Locator）

**描述**：模块间通过容器或服务定位器解耦。

**设计文档典型描述**：
> "M04 通过依赖注入获取 M07 的缓存服务实例"

**代码验证方法**：
- 检查 DI 容器的配置文件中是否注册了对应的服务绑定
- 检查模块 A 是否通过构造函数或属性注入获取了模块 B 的接口
- 检查模块 B 的接口定义是否与模块 A 的使用方式匹配

> ⚠️ **注意**：此模式静态检查难度较高，如无法确认，在报告中标记为"❓ 无法验证"

---

## 模式 7：回调/钩子（Callback/Hook）

**描述**：模块 B 注册回调函数到模块 A，模块 A 在特定时机调用。

**设计文档典型描述**：
> "M05 向 M03 注册订单完成后的回调函数"

**代码验证方法**：
- 在模块 B 中搜索 `register_callback`、`add_listener`、`on_complete` 等
- 在模块 A 中搜索回调调用点（如 `for cb in callbacks: cb(...)`）
- 检查回调注册时机（启动时 vs 运行时）

---

## 模式 8：配置/路由注册（Configuration）

**描述**：模块通过配置文件或路由表连接。

**设计文档典型描述**：
> "M08 的处理器在 `main.py` 中注册到路由 `/api/v1/tasks`"

**代码验证方法**：
- 检查 `main.py`、`app.py`、`routes.py` 等入口文件
- 搜索模块的导入和注册语句
- 检查路由路径、中间件绑定、事件处理器注册等

---

## 审查提示

1. **优先检查设计文档明确描述的联动**，不要自行推断额外的联动关系
2. **一个模块可能同时参与多种联动模式**（如既同步调用，又通过事件通信）
3. **标记"❓ 无法验证"好过盲目猜测**：如果代码经过高度动态化组装（如反射、动态 import），如实记录无法静态验证
4. **数据结构一致性是常见问题**：即使调用关系存在，DTO/模型字段不匹配也会导致联动失败
