# 功能规格文档输出模板（索引）

> `module-spec-writer` 的输出基于已冻结的意图文档，生成两份技术文档。

## 流水线关系

```
module-intent-writer → [编号]-[名称]-意图文档.md（已冻结）
                              ↓
                    module-spec-writer
                              ↓
              ┌───────────────┴───────────────┐
              ▼                               ▼
    [编号]-[名称]-设计文档.md      [编号]-[名称]-落地规范.md
      （瘦身版，维护者看）            （Code Agent 看）
```

## 模板文件

| 文件 | 面向读者 | 用途 |
|------|----------|------|
| `human-design-template.md` | 维护者、架构师 | 瘦身版设计文档：技术实现思路、架构权衡、兼容性分析 |
| `agent-spec-template.md` | Code Agent | 落地实现规范：精确类型、接口契约、状态转换表、异常阈值、验收测试 |

## 文档定位

| 维度 | 意图文档（前置） | 设计文档（瘦身版） | 落地规范 |
|------|---------------|------------------|---------|
| **读者** | 业务方、测试人员 | 维护者、架构师 | Code Agent |
| **核心问题** | "做到什么程度算完成？" | "为什么这样实现？" | "具体怎么写？" |
| **稳定性** | 冻结后不可变 | 随技术演进可调整 | 随技术演进可调整 |

## 冻结与回退机制

- **意图文档冻结**：module-intent-writer 生成意图文档后，必须通过用户显式"冻结授权"，文档标记为 `已冻结`
- **spec-writer 强制依赖**：module-spec-writer 只能以已冻结的意图文档为输入
- **回退机制**：spec-writer 发现意图文档存在技术不可行项时，无权自行妥协，必须标记为"意图缺陷"并回退到 intent-writer 修正

## 历史说明

v3.0 之前，本 Skill 输出设计文档 + 落地规范两份文档，设计文档混合了业务描述与技术实现。
v3.0 起引入意图文档作为前置输入，设计文档瘦身为纯技术视角，形成"意图 → 设计 → 规范"三层流水线。
