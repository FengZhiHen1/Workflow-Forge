# AskUserQuestion 使用示例

本文件存放 module-intent-writer 中所有 AskUserQuestion 调用的完整示例，供 Skill 执行时按需参考。

---

## 示例 1：核心模块首轮提问（Step 4-A.1）

```
调研背景：模块 M02（世界观构建引擎）对应总设计 3.2 节，上游为 M01，
下游为 M03/M05。已审查契约索引，无冲突。以下为首轮业务决策点。

AskUserQuestion({
  questions: [
    {
      question: "世界观构建的'完整性'如何定义？用户可能只需要基础设定，也可能需要全维度详细设定。",
      header: "业务完整性",
      options: [
        { label: "全维度强制生成 (Recommended)", description: "每次必须生成基础设定+文化细节+地理环境三个维度，不允许用户选择部分维度" },
        { label: "允许用户选择维度", description: "用户可勾选需要哪些维度（如只选基础设定），更灵活但实现更复杂" }
      ]
    },
    {
      question: "当生成超时但已产出部分内容时，业务上应如何处理？",
      header: "超时降级",
      options: [
        { label: "展示草稿并让用户决定 (Recommended)", description: "用户可预览部分结果，选择继续等待或接受草稿" },
        { label: "直接提示失败", description: "用户看不到任何结果，体验较差但逻辑简单" },
        { label: "自动后台重试", description: "自动重新生成，用户无感知，但可能产生额外成本" }
      ]
    },
    {
      question: "世界观生成结果是否允许用户编辑后再保存？",
      header: "用户编辑",
      options: [
        { label: "允许编辑后保存 (Recommended)", description: "用户可修改 AI 生成的内容再保存，更实用" },
        { label: "仅允许接受或重新生成", description: "不允许编辑，用户只能选择用或不用" }
      ]
    }
  ]
})
```

## 示例 2：核心模块书写授权（Step 4-A.4）

```
经过 3 轮问答，本模块的所有关键业务决策点已明确：

- 业务边界：接收上游 M01 的题材/风格标签，产出世界观设定给下游 M03/M05
- 输入/输出：题材类型（必填，枚举值）、风格标签（可选）、世界观文本（三维度）
- 状态机：空闲→构建中→已完成/失败，含草稿降级
- 业务规则：全维度强制生成、允许用户编辑后保存
- 验收标准：一致性率 ≥ 95%、完整性三维度覆盖率 ≥ 95%
- 留给规范阶段：具体超时秒数、重试次数、Pydantic 类型定义

AskUserQuestion({
  questions: [
    {
      question: "所有业务需求已澄清完毕。是否授权开始生成意图文档？\n- `M02-世界观构建引擎-意图文档.md`",
      header: "书写授权",
      options: [
        { label: "开始生成", description: "立即进入 Step 5，生成意图文档" },
        { label: "还需要补充", description: "还有未覆盖的决策点，回到澄清循环继续提问" }
      ]
    }
  ]
})
```

## 示例 3：核心模块冻结授权（Step 6）

```
意图文档已生成。请确认以下核心内容是否已锁定：
- 业务边界：接收上游 M01 的题材/风格标签，产出世界观设定给下游 M03/M05
- 验收标准：一致性率 ≥ 95%、完整性三维度覆盖率 ≥ 95%、用户可编辑后保存
- 关键业务规则：全维度强制生成、超时展示草稿让用户决定

留给规范阶段的技术决策已明确列出：超时秒数、重试策略、Pydantic 类型、状态机技术实现。

AskUserQuestion({
  questions: [
    {
      question: "冻结后，本文档将作为后续技术规格编写的强制输入，不可擅自修改。如需修改，必须通过回退机制重新解冻。是否确认冻结？",
      header: "冻结授权",
      options: [
        { label: "冻结确认 (Recommended)", description: "意图文档已锁定，标记为冻结状态，允许进入规范编写阶段" },
        { label: "还需要修改", description: "意图文档还有需要调整的地方，返回修改" }
      ]
    }
  ]
})
```

## 示例 4：一般模块快速授权（Step 4-B.2）

```
经过自检，模块 [编号]（[名称]）的以下维度已确认清晰：
- 业务边界：[一句话描述]
- 输入/输出：[可从设计文档直接推断业务含义]
- 业务规则：[使用行业默认规则]
- 状态机：[无 / 已在设计文档中描述]
- 兼容性：[无冲突]

AskUserQuestion({
  questions: [
    {
      question: "本模块标记为一般功能模块，业务需求已足够清晰。是否直接生成意图文档？\n- `[编号]-[名称]-意图文档.md`",
      header: "快速授权",
      options: [
        { label: "直接生成 (Recommended)", description: "基于现有设计文档直接输出意图文档，不再追加问答" },
        { label: "切换到全量澄清", description: "认为该模块需要更严格的需求对齐，进入核心模块的多轮问答流程" }
      ]
    }
  ]
})
```

## 示例 5：冻结后修改请求的处理

```
用户要求对已冻结的意图文档进行修改。

处理流程：
1. 先用文本说明："该意图文档已于 [冻结时间] 冻结。修改后需要重新冻结。"
2. 记录用户的具体修改意见
3. 修改文档内容
4. 修改完成后，再次调用 AskUserQuestion 请求冻结授权（同示例 3）

AskUserQuestion({
  questions: [
    {
      question: "文档已根据您的意见修改。请确认修改后的内容，并重新授权冻结。",
      header: "重新冻结",
      options: [
        { label: "冻结确认 (Recommended)", description: "修改后的意图文档已锁定，重新标记为冻结状态" },
        { label: "还需要修改", description: "继续调整" }
      ]
    }
  ]
})
```
