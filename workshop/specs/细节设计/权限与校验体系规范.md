# 权限与校验体系规范 v3.0.0

---

## 〇、设计原则

**依赖架构，不依赖自觉。** 不要求 AI 遵守规则——用物理隔离保证它无法越界，用事后校验证明它确实没有越界。

---

## 一、四层防线

| 层 | 时机 | 机制 | 性质 |
|----|------|------|------|
| ① worktree 隔离 | SubAgent 运行中 | 物理屏障——SubAgent 不知 `project_root`，世界仅限于自身 worktree | 预防 |
| ② wfctl 事后校验 | SubAgent 上报完成时 | 比对 `modified_files` 与保护区，检测是否越界 | 检测 |
| ③ git 锚点可逆 | 违规后任意时刻 | 从锚点检出覆盖违规变更 | 恢复 |
| ④ prompt 禁令 | SubAgent 运行中 | 通用契约中的硬禁令，SubAgent 启动时自行读取 | 兜底 |

① 和 ② 是核心。③ 是补救。④ 是最后一道心理防线——架构已保障，禁令只是提醒。

---

## 二、worktree 隔离

### 2.1 核心机制

SubAgent 从 `wfctl identity` 获取的身份参数**不包含** `project_root`：

| 参数 | 用途 |
|------|------|
| `instance_id` | 标识所属实例 |
| `stage_id` | 标识所属 stage |
| `stage_instance_id` | parallel 时区分实例 |
| 消息投递路径 | 调用 `wfctl message write` 时的目标路径（相对 worktree 内部） |

SubAgent 的工作目录即为其 worktree。它不知道主仓库存在哪里，无法 `cd` 到主仓库或其他 stage 的 worktree。

### 2.2 穿透通道

SubAgent 与主仓库的唯一通信通道是 `wfctl message write`——wfctl 内部将消息写入主仓库 `.agent/instances/<id>/messages/`，不经过 worktree。SubAgent 不感知写入路径，只调用命令。

---

## 三、wfctl 事后校验

### 3.1 校验时机

`next` 消费 SubAgent 的 DONE/AWAITING_CONFIRM 消息时，wfctl 通过 `git -C <worktree> status --porcelain` 获取变更文件列表，注入 `modified_files`。

### 3.2 保护区定义

| 路径 | 说明 |
|------|------|
| `.agent/` | 运行时状态目录 |
| `.git/` | 版本库 |
| `.tmp/worktrees/` 下非本 stage 的 worktree | 其他 stage / 实例的工作空间 |
| 主仓库工作区（非 `.tmp/` 下的所有路径） | 源码、配置、文档等 |

SubAgent 的 `modified_files` 应在自身 worktree 范围内。任何越界即违规。

### 3.3 违规处理

不做分级。统一处理：

1. Stage → `ERROR`
2. 写入 deviation 日志：

   ```json
   {"timestamp":"...","type":"ACCESS_VIOLATION","stage_id":"s03","files":["../.agent/config.json"],"action":"stage→ERROR + rollback"}
   ```

3. 从该 stage 的锚点回退 worktree 变更（`git checkout wf-<instance_id>-<stage_id>`）

如果下一轮 retry 中再次违规，走常规 ERROR 分支（retry → failure edge → 耗尽 → terminate）。

---

## 四、锚点可逆

违规修改被检出覆盖后，git reflog 保留回退前的状态 30 天。开发者可通过 `git reflog` 检查违规时做了什么修改，用于分析问题。

锚点规范详见 `worktree与git锚点规范` §六。

---

## 五、prompt 禁令

### 5.1 载体

通用契约 `artifacts/contracts/common.md`（消费者项目中为 `.claude/contracts/common.md`）。

主 Agent 不读取、不转述契约内容。启动 SubAgent 时在 prompt 中注入如下指令：

> 在开始工作前，阅读 `.claude/contracts/common.md`。该文件包含你必须遵守的硬禁令。违反禁令将导致你的 stage 被标记为 ERROR 并回退。

### 5.2 禁令内容

| 禁令 | 说明 |
|------|------|
| 不得离开 worktree 工作目录 | SubAgent 的所有文件操作必须在自身 worktree 内 |
| 不得读取或写入 `.agent/` | 运行时状态目录，仅通过 `wfctl message write` 间接通信 |
| 不得执行破坏性 Git 操作 | 禁止 `git push`、`git reset --hard`、`git clean -f`、修改 `.gitconfig` |
| 不得访问网络或执行系统级命令 | 禁止 `curl`、`wget`、`npm install -g`、`pip install`（非隔离环境） |

### 5.3 禁令的定位

禁令是**兜底**而非依赖。如果 SubAgent 忽略禁令——worktree 隔离已从物理上阻断越界。如果隔离被绕过——事后校验会检测到违规并回退。禁令存在的意义是减少"明知故犯"的概率，降低校验被触发的频率。
