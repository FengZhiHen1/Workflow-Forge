# 目录规范 v3.0.0

---

## 1. 仓库定位

本仓库是工作流体系的**生产车间**，承担三重角色：

1. **规范演进场**——工作流协议、契约、状态机的制定与迭代
2. **生产车间**——工作流与 Skill 的设计、实现与维护
3. **分发源头**——所有消费者项目通过 `workflow-env-init` 从本仓库拉取工件

---

## 2. 总体分区

仓库根目录按资产性质划分为三个区：

```
.
├── workshop/           # 车间区：规范 + 模板 + 参考 + 归档
├── artifacts/          # 产物区：分发到消费者项目的工件
├── .claude/            # 车间自用：Claude Code 原生维护 Skill
├── .agent/             # 运行时产物（gitignore）
├── .tmp/               # 临时草稿（gitignore）
├── .gitignore
├── CLAUDE.md
├── AGENT.md
└── README.md
```

| 区 | 可见性 | 版本控制 | 分发 |
|----|--------|---------|------|
| `workshop/` | 可见 | ✅ | 不分发 |
| `artifacts/` | 可见 | ✅ | 被 `workflow-env-init` 拉取 |
| `.claude/` | 隐藏 | ✅ | 不分发 |
| `.agent/` | 隐藏 | ❌ gitignore | 不分发 |
| `.tmp/` | 隐藏 | ❌ gitignore | 不分发 |

**设计原则**：可见即源码（workshop + artifacts），隐藏即运行时或工具内部。

---

## 3. 车间区（`workshop/`）

```
workshop/
├── specs/              # 现行规范文档
├── templates/          # 标准模板（创建新工作流/Skill/契约的模具）
├── reference/          # 参考资料（有借鉴价值但非现行）
└── archive/            # 归档（已被取代，仅保留历史痕迹）
```

### 3.1 `specs/` — 现行规范

| 项 | 内容 |
|----|------|
| **职责** | 定义工作流体系的协议、契约、状态机——体系"宪法" |
| **读者** | 人类开发者、AI Agent |
| **写入者** | 体系设计者 |
| **内容** | workflow规范、message规范、skill规范、目录规范等现行有效的规范文档 |

### 3.2 `templates/` — 标准模板

| 项 | 内容 |
|----|------|
| **职责** | 创建新工作流、Skill、契约、Message 时使用的标准模板——车间模具 |
| **读者** | Skill 作者、工作流设计者 |
| **内容** | WORKFLOW.template.md、WORKFLOW.template.yaml、skill.template.md、message.template.json 等 |

**约束**：仅供车间内部使用，不参与分发。

### 3.3 `reference/` — 参考资料

| 项 | 内容 |
|----|------|
| **职责** | 存放仍有参考价值但非现行业务的内容 |
| **读者** | Skill 作者、工作流设计者 |
| **约束** | 只读借鉴，**禁止被工作流编排器直接调度**。放入时标注预期保留期限，过期后自动移入 `archive/`，避免退化为模糊地带 |
| **内容** | 旧版 Skill（仅供借鉴业务逻辑）、外部 API/工具文档、设计笔记/随笔 |

### 3.4 `archive/` — 归档

| 项 | 内容 |
|----|------|
| **职责** | 存放已被取代的内容，仅保留历史痕迹 |
| **内容** | 已废弃的规范文档、过时文档 |

**`reference/` 与 `archive/` 的边界**：
- `reference/`：仍有参考价值，可以从中借鉴思路
- `archive/`：已被新版本完全取代，仅作历史存档

## 4. 产物区（`artifacts/`）

```
artifacts/
├── workflows/          # 工作流定义（含局部 Skill）
├── skills/             # 全局 Skill
├── archive/            # 被替代的旧版本
│   ├── workflows/
│   └── skills/
├── contracts/          # 通用契约
└── scripts/            # 基础设施脚本
```

### 4.1 `workflows/` — 工作流定义

**命名约束**：`<workflow_id>@<version>/`

每个工作流目录固定包含：

```
<workflow_id>@<version>/
├── WORKFLOW.md          # 人类可读：名称、概览、Mermaid 流程图
├── WORKFLOW.yaml        # 机器规范：stages、edges、并发规则
├── skills/              # [可选] 局部 Skill（仅本工作流使用）
├── scripts/             # [可选] 工作流级脚本
└── references/          # [可选] 工作流级共享参考
```

**现行规则**：`artifacts/workflows/` 下每个工作流仅保留最新版本。旧版本移入 `artifacts/archive/workflows/`。

### 4.2 `skills/` — 全局 Skill

**命名约束**：`<skill_id>/`，kebab-case，与目录名严格一致。

```
<skill_id>/
├── SKILL.md             # Skill 主文件
├── references/          # [可选] 专用契约及其他参考
└── scripts/             # [可选] Skill 级脚本
```

**版本管理**：
- 现行版本不加版本号（`<skill_id>/`），所有工作流默认浮动引用最新
- 需要不兼容升级时，旧版保留为 `<skill_id>@<ver>/`（如 `topic-analyst@1.0.0/`），新版替换现行目录
- 已无工作流引用的旧版本移入 `artifacts/archive/skills/`
- 局部 Skill 无版本管理——随工作流版本自然锁定

**全局 vs 局部 Skill 边界**：
- 被 2 个及以上工作流引用的 Skill → `artifacts/skills/`（全局）
- 仅被 1 个工作流引用的 Skill → 该工作流目录下的 `skills/`（局部）
- 两者**绝对不可合并**

### 4.3 `archive/` — 旧版本归档

```
archive/
├── workflows/           # 被新版本替代的旧版工作流（全版本迁移）
└── skills/              # 被新版本替代的旧版全局 Skill
```

**归档规则**：同一个工作流或 Skill 的新版本发布后，旧版本从现行区移入对应 archive 子目录。已归档版本不向消费者重复提供——消费者应迁移到现行版本。

### 4.4 `contracts/` — 通用契约

| 文件 | 职责 |
|------|------|
| `common.md` | 通用契约：硬禁令、文件系统限制、Git 操作禁令、降级熔断 |
| `input.md` | 通用输入契约：编排器注入的全部输入字段定义 |
| `output.md` | 通用输出契约：SubAgent 必须上报的全部字段定义 |

**约束**：所有 Skill 强制读取；缺失则上报 ERROR。

### 4.5 `scripts/` — 基础设施脚本

面向所有 Skill 和编排器的全局脚本：

| 脚本 | 职责 |
|------|------|
| `write_message.py` | Message 标准化写入（原子写入 + Schema 校验） |
| `validate_instance.py` | 工作流实例完整性校验 |
| 其他 | 编排器依赖的辅助脚本 |

## 5. 隐藏目录

### 5.1 `.claude/` — 车间自用

存放本仓库自身的 Claude Code 维护 Skill（optimizer、transformer、efficiency-optimizer）。

| 约束 | 说明 |
|------|------|
| 路径 | `.claude/skills/`，不动 |
| 分发 | 不被分发到消费者项目 |
| 版本控制 | ✅ 纳入 |

### 5.2 `.agent/` — 运行时状态

工作流实例状态机、Message 通信池、备份。完全由编排器管理。

### 5.3 `.tmp/` — 临时草稿

SubAgent 过程产物、文档草稿、中间数据。工作流结束后可清理。

---

## 6. 路径标准化规则

1. **以项目根为基准**：相对路径，无 `./` 前缀，无 `../`，无 `//`
2. **统一分隔符**：`/`
3. **目录结尾**：仅目录路径以 `/` 结尾，文件路径不以 `/` 结尾

---

## 7. 与消费者项目目录的对应关系

本仓库为生产车间，`artifacts/` 下的工件在消费者项目中按以下映射部署：

| 生产车间（本仓库） | 消费者项目 |
|-------------------|-----------|
| `artifacts/workflows/<id>@<ver>/` | `.claude/workflows/<id>@<ver>/` |
| `artifacts/skills/<id>/` | `.claude/skills/<id>/` |
| 局部 `workflows/<id>@<ver>/skills/<id>/` | `.claude/skills/<id>/`（拉取时汇总到同一目录） |
| `artifacts/contracts/` | `.claude/contracts/` |
| `artifacts/scripts/` | `.claude/scripts/` |

消费者项目目录规范详见 Workflow 规范 v2 中的文件体系章节。
